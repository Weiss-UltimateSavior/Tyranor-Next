fix(rpgmaker): MZ 1.2+ 与 Effekseer 关闭时的两处启动断链

真机日志（11_28-18-44-40_084.log:6494-6502，RPG Maker MZ 1.9.0 样本）显示游戏
完全无法加载：Main.run() 第一句就抛
  TypeError: nw.Window.get(...).on is not a function
于是 loadMainScripts() 从未执行，rmmz_core.js 一个请求都没发出，画面全黑，
而 15s 启动超时把这种失败伪装成「揭开得慢一点」。

两处根因，都是接口面与 corescript 实际调用不符：

1. NW.js 垫片的窗口桩没有事件接口。MZ 1.2.0 起 Main.run() 会先调
   nw.Window.get().on("close", ...)（hookNwjsClose）。补齐 EventEmitter 语义
   （on / once / addListener / removeListener / removeAllListeners / emit），
   once 与 removeListener 互相可解除。该文件与 MV 共用，但只是新增方法，
   MV 三条链路的 harness 回归全绿。
   注：nw.App.argv / nw.App.quit() / chrome.runtime.reload() 一类调用被
   Utils.isNwjs() 门控，宿主钉 false 后不可达，无需处理。

2. Effekseer 桩的形态错了。MZ 的 main.js 在 initEffekseerRuntime() 里
   **无判空**地调 effekseer.initRuntime(wasmUrl, onLoad, onError)，而 onLoad 是
   SceneManager.run(Scene_Boot) 的唯一入口。原桩把 window.effekseer 永久置成
   undefined（getter return undefined），这行必然抛错、启动断在场景之前。
   改为静默桩：保留 initRuntime 并按成功路径回调 onLoad，只让 createContext
   返回 null——Graphics 对空 context 是容忍的（Sprite_Animation 直接不播），
   既阻止 WASM 实例化，也不影响启动。

回归（都先 RED 后 GREEN）：
- harness 9i：窗口桩必须提供 on/once/removeListener/emit 且能真的派发 close
- harness 9j：按 MZ 1.2 的 Main.run() 顺序跑完并走到 loadMainScripts
- harness 9k：按这台设备真实的 MZ 1.9.0 main.js 跑启动链，桩生效时仍到
  SceneManager.run，且 createContext 不创建 context
- 9a/9h 按新语义更新（桩保留而非抹掉全局）

真机验证：安装该 APK 后启动同一款游戏，rmmz_core.js 正常求值、插件 mz3d.js
打完「Finished loading external data」、图片资源正常回退加载，游戏可玩。
