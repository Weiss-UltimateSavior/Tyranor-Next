# 第三方 APK 运行时模块单游戏引擎配置与存档管理计划

> 日期：2026-11-17。状态：已实现；本文保留功能设计与实施计划。
> 用户确认范围：增加单游戏引擎配置，以及指定游戏目录内存档目录的统一管理；不增加全局配置、全局设置页或模块管理页设置入口。
> 当前行为仍以 [SPEC.md](../SPEC.md)、[ARCHITECTURE.md](../ARCHITECTURE.md) 和代码为准。
> 关联：[模块接入指南](第三方APK运行时模块接入指南.md)、[原接入方案](第三方APK运行时模块接入方案.md)、[Ren’Py 模块分析](renpy-8.5.3-module-analysis.md)。

## 1. 目标与边界

为已绑定第三方 APK 运行时模块的游戏按能力增加抽屉内的「引擎设置」和「存档管理」入口。模块声明设置项与游戏内存档子目录，主 App 保存并下发单游戏配置，将声明的存档目录纳入统一管理。

- 生效顺序：合法的单游戏覆盖值 → 模块声明默认值。页面不出现「跟随全局」。
- 支持布尔、枚举、文本、整数四类设置，提供保存与「恢复默认」。
- 配置按游戏 URI 与模块包名共同隔离；模块名、游戏标题不是配置身份。
- 不新增全局配置，不改变模块管理、扫描入库、模块启用与绑定降级规则。
- 模块声明游戏目录内的一个存档子目录，主 App 将其接入统一存档管理（导入、导出、删除、版本管理与 WebDAV 同步）；模块仍负责实际读写存档和运行效果，不接管其运行时、按键、图形实现或模块本地配置文件。
- 不改变 Ren’Py、RPG Maker RGSS、Ruffle 的 JoiPlay 外置 APK 引擎模块协议或现有设置页。

## 3. 模块声明协议

### 3.1 可选 settings 字段

在现有 `res/raw/tyranor_runtime.json` 顶层增加 `settings`，与 `scan` 独立解析。示例：

```json
{
  "protocol": 1,
  "scan": { "match": "any", "extensions": [".mygame"] },
  "settings": {
    "version": 1,
    "items": [
      { "key": "vsync", "type": "boolean", "title": "垂直同步", "default": true },
      {
        "key": "renderer", "type": "enum", "title": "渲染后端", "default": "auto",
        "options": [
          { "value": "auto", "title": "自动" },
          { "value": "vulkan", "title": "Vulkan" }
        ]
      },
      { "key": "player_name", "type": "text", "title": "玩家名称", "default": "", "maxLength": 64 },
      { "key": "fps_limit", "type": "integer", "title": "帧率上限", "default": 60, "min": 30, "max": 120 }
    ]
  }
}
```

这是 v1 启动协议的可选增量能力，保留 `PROTOCOL_VERSION = 1` 及所有旧 extra。`settings.version` 是设置描述格式版本；首版只解释 1，未知版本只关闭设置能力，不拒绝发现、扫描或原路径启动。

根 `protocol` 沿用当前发现逻辑，只作描述信息，不新增兼容门控；是否支持本次能力只由合法的 `settings.version = 1` 与设置描述决定。模块仍按主 App 实际发送的启动版本 1 消费基础参数，不能因根字段填了其它版本就假定主 App 实现了该版本。

### 3.2 输入约束

- 沿用现有描述文件 64 KiB 和 JSON 嵌套深度上限；设置最多 32 项，每项 key 为 `[A-Za-z][A-Za-z0-9_]{0,63}`，大小写敏感。
- 重复 key 只接受第一个合法项；未知类型、缺失标题、非法默认值整项丢弃，不静默猜类型。
- `boolean` 默认值必须为 JSON 布尔，整数必须无小数且处于 Int 范围，不把字符串、布尔隐式转成数字。
- `integer` 必须给出合法 `min`、`max`，且 `min <= default <= max`；保存时拒绝越界输入，启动时失效覆盖回退默认值，不截断成边界值。
- `enum` 最多 32 个选项，值为非空字符串，长度最多 64 字符；去除重复值和非法选项后，默认值必须仍在选项内。
- `text.maxLength` 为 1–1024，缺省为 256；默认值和输入均受限，不自动 trim 用户文本。首版仅支持单行普通文本，不设计密码、文件选择或脚本执行字段。
- 字符串长度统一按 UTF-16 code unit（Kotlin `String.length`）计数，所有文本须为合法 Unicode，不接受孤立代理项。单行文本拒绝 C0/C1 控制字符及 U+2028/U+2029，明确不支持换行和制表符；JSON 由统一编码器转义。容量计算中 text 采用 `6 × maxLength + 2` 字节的保守 JSON 字符串上界，枚举采用合法选项编码后最大 UTF-8 长度，整数采用范围内最长十进制表示；加上 key 与结构开销后整体不得超限。
- 标题必填、最多 128 字符；可选说明最多 512 字符。模块文案作为普通文本显示，不解释 HTML、Markdown 或可执行内容。
- 首版模块标题、说明和选项标题直接使用声明字符串；主 App 的保存、恢复、错误提示等固定文案提供中、日、英三语言。模块文案的多语言声明留待后续。
- `RuntimeModuleManifest` 分别携带 scan、settings 与 saves，三块各自容错解析：任一块非法不能清空其它有效能力，只有整个 JSON 无效时三者都不可用。单个非法设置项丢弃该项，未知 settings 版本或总预算超限关闭整块设置能力；最终无有效设置项时隐藏设置入口。saves 的严格版本与目录字段校验见第 7 节，失败只关闭 saves。

## 4. 配置存储与解析

### 4.1 存储形态

在单游戏覆盖记录增加具名子对象，示意：

```json
{
  "runtime_module_settings": {
    "com.tyranor.runtime.example": {
      "vsync": false,
      "fps_limit": 90
    }
  }
}
```

- 外层记录以游戏 URI 为键，内层以完整模块包名隔离；只保存覆盖值，不复制标题、选项和默认值。
- 在 `PerGameSettingsStore` 暴露专用读取、保存、清除当前模块配置 API，UI 不直接操作 prefs、数据库或协议 JSON。
- 在 `GameOverridePartitions` 中将顶层 `runtime_module_settings` 显式登记到既有 tyrano JSON 分区，组装时还原同名子对象；这是存储列复用，不表示第三方模块属于 Tyrano 引擎。利用现有 JSON 分区，不为本功能新增 Room 列或 schema 版本。实施前核对组装、备份、导入导出和清理链路不会丢失子对象。
- 保存一次性更新当前模块子对象，保留同游戏其它模块配置及既有引擎、输入、图形覆盖；不能逐字段覆盖整条记录导致无关数据丢失。
- 现有 `GameOverridesRepository.updateRecord` 只更新缓存并投递异步 DB 写入，`PerGameSettingsStore.persist` 使用 prefs `apply()`，都不提供可等待的持久化成功结果。本次须增加可等待、返回类型化结果的保存门面，并与既有写队列协调；不能仅调用旧接口后就提示保存成功。取消原样传播。
- 同游戏配置的读—合并—写在存储门面的同一串行操作中完成，覆盖记录以提交时的最新状态为基础；核对与现有整条记录写入、清除操作的顺序，不能只给新页面加锁。DB 与 prefs 无跨存储事务，实施时须在该门面明确写入顺序、失败恢复及重启回灌策略，测试覆盖任一步骤失败，不以「DB 已写」掩盖镜像失败或旧镜像回灌。
- 卸载、禁用、绑定降级时保留配置；同包名恢复并经重扫重新绑定后可继续使用。游戏移除及设置清理沿用仓库既有策略，明确验证嵌套字段的处理结果，不额外扩展保留策略。

### 4.2 生效规则

由 core 的统一解析函数使用「当前发现的模块描述 + 当前游戏覆盖」生成类型化生效配置：

1. 只遍历当前模块有效声明的 key。
2. 覆盖值类型、长度、范围或枚举取值合法时采用覆盖，否则采用声明默认值。
3. 删除的字段、未知 key 不下发；新增字段采用新默认值。描述变化不自动改写磁盘数据。
4. 模块更新导致有效覆盖不再合法时，设置页显示实际回退值并提示相关项已恢复默认；保存时仅保留当前有效字段，清除当前模块的失效字段。
5. 设置页与启动器共用同一解析函数；不把 Ren’Py 的全局合并模型接到第三方模块上。

## 5. 页面与交互

- `GameActionsSheet` 订阅注册表状态；游戏必须仍为 `RUNTIME_MODULE`、有包名，且模块已发现、已启用、有有效设置项，才显示「引擎设置」。每次打开抽屉异步刷新一次，加载与失败使用公共反馈；已有成功快照时保留原入口，进入页后重新核对，无成功快照时显示加载或重试状态，不把查询失败当成模块卸载。刷新协程随抽屉组合取消，结果不负责打开或重新选择抽屉，避免关闭后异步回调将其唤回。
- 点击后复用 `PerGameSettingsActivity` 的输入校验、主题与页面转场，在 Activity 调用设置 Composable 时按引擎类型分流到 `ui/runtime/` 的第三方模块设置内容；分流发生在调用 `PerGameSettingsScreen` 之前，避免执行既有设置页的全引擎读取和保存逻辑。
- 页面使用公共二级顶栏和透明页面背景，正文直接展示设置项；布尔使用公共 `SwitchPreference`，枚举使用公共 `OverlayDropdownPreference`，文本与整数编辑复用 `AppSearchField` 和标准弹窗。
- 文案使用「默认值」或「恢复默认」，不出现「全局」与「跟随全局」。默认值未被覆盖的字段在下次模块默认值改变后随之变化；用户显式保存的覆盖值保持不变。
- 顶部保存一次提交当前模块覆盖。保存成功后更新已保存快照，再显示成功反馈；失败映射类型化错误并保留编辑内容，不能假报成功。
- 「恢复默认」先将编辑草稿的覆盖清空，点击保存后才持久化；逐项也可恢复默认。保存时不把未修改的默认值固化为覆盖。
- 编辑草稿和已保存基线通过 Activity SavedState／`rememberSaveable` 可序列化状态恢复，携带游戏 URI、模块包名和规范化描述指纹；旋转与系统进程重建后先恢复草稿，再异步重新发现并核对描述，不把草稿自动保存到配置存储。返回时有未保存改动则使用现有标准确认弹窗，未改动直接返回。
- 加载、失败、空设置、刷新后能力消失均有明确展示。页面恢复前台时重新发现；模块失效时停止编辑和保存，不用旧描述继续提交；刷新失败保留草稿并允许重试，不解释为模块卸载。
- 页面加载、恢复前台及保存前，经 core 重读当前游戏库条目，确认游戏仍存在、`engine == RUNTIME_MODULE` 且 `runtimeModulePackage` 与页面目标一致；不能仅以 Activity 传入的 `ScanGame` 快照为依据。游戏被移除、降级或重新识别后暂停保存并提示返回刷新，不自动改绑。
- 保存前刷新并核对模块包名、启用状态和规范化设置描述指纹；查询失败拒绝本次保存并保留草稿供重试。描述改变则提示用户核对，不把旧草稿按新声明静默保存；存储提交仍需检查对应游戏绑定，避免验证与提交之间的库变更被忽略。
- 描述改变且有未保存修改时，保留旧草稿、暂停保存并显示冲突提示；用户明确选择放弃旧草稿后才按新描述重载，不自动丢弃或迁移草稿。无修改时直接重载。模块暂不可用或查询失败时保留草稿供重试，恢复后只有指纹一致才恢复编辑；保存期间禁用重复提交，不能只靠页面内存状态规避并发存储问题。
- 不复制动效实现，使用已有公共控件、加载反馈、内容替换和抽屉导航入口；核对首页与游戏库、普通与增强动效档的行为。

## 6. 启动参数与兼容

新增常量（实施时以此拼写为契约）：

```text
RuntimeModuleContract.EXTRA_SETTINGS = "com.tyranor.runtime.extra.SETTINGS"
```

该 extra 类型为 String，内容为 JSON：

```json
{ "version": 1, "values": { "vsync": false, "renderer": "auto", "player_name": "", "fps_limit": 90 } }
```

- 仅向当前绑定、启用且声明有效设置能力的模块发送；没有设置能力的模块不附加该 extra，保持旧启动载荷。
- 使用 `EngineLauncher.launchRuntimeModule` 已刷新的模块描述，在启动前读取覆盖并统一解析，再由 `RuntimeModuleLauncher` 编码。数据库读取和描述解析走 IO，不在 Compose 主线程阻塞。
- 下发完整生效配置，保留 boolean、string、integer 的 JSON 类型；不使用 JoiPlay 的 `app` / `renpy` 或 `{ "boolean": ... }` 包装。
- UTF-8 配置载荷上限 48 KiB。声明解析时计算所有字段在允许取值下的序列化大小上界，包含 JSON 键、结构、引号与转义开销（文本不能按字符数直接当字节数）；总上界超限则关闭该模块设置能力，保留扫描和原路径启动，并在诊断中说明原因。不能只限制单字段后允许合法用户输入在启动时必然超限。编码后再次检查；意外超限或配置读取失败使用既有类型化启动失败体系，不悄悄丢配置后继续启动。
- 原有 action、显式组件、目录、标题、协议版本与无 URI 授权行为保持一致。`Dispatched` 仍只表示交棒成功。
- 接入指南明确要求模块按 key 白名单和类型读取；本次传入值优先于模块本地同名配置。未收到 extra 时沿用模块原有默认行为；载荷 JSON 无法解析或 version 不支持时整份忽略并记录原因，已支持版本中的未知 key 忽略，已知字段非法或缺失时使用模块自身声明默认值，不将类型错误的值应用到运行时。
- 主 App 不读写第三方模块的 `configuration.json`。模块开发者需要主动实现参数消费，增加主 App 设置页本身不能保证模块已经支持运行效果。

## 7. 游戏目录内存档目录与统一管理

### 7.1 声明与范围

在同一个模块描述文件顶层增加独立可选的 `saves` 能力，例如：

```json
{
  "saves": {
    "version": 1,
    "directory": "data/save"
  }
}
```

- `directory` 是相对于本次启动游戏目录（`FOLDER_PATH`）的存档目录，例如 `save`、`saves`、`data/save`。每个模块只声明一个固定子目录，各游戏以各自游戏根解析；可包含目录内的多层存档文件。
- 首版由模块明确声明实际使用的路径，不把普通 text 设置项当作可删除/同步的存档目录。用户不任意选择游戏外目录，也不新增全局存档路径。模块必须保证所有受管理存档均位于该目录，该目录不混放游戏资源、脚本或运行库。
- `saves.version` 首版仅支持整数 1。与 scan/settings 独立解析：可以只提供存档能力、不提供设置项；没有有效 saves 时维持现有无统一存档接口行为。整个描述 JSON 无效时三个能力都不可用。
- saves 缺失表示未声明；非对象、version 缺失/非整数/非 1、directory 缺失/非字符串/空/超长或不符合路径规则，均只令 saves 无效并记录诊断，保留有效 scan/settings。静态非法描述与运行时目录暂不可用分开处理；前者不建立新文件接口，后者保留已声明能力和身份占用。
- 不新增存档路径 extra，不把路径混入 settings values；模块按照自己的声明和已有 `FOLDER_PATH` 定位，主 App 按同一基准解析。声明本身不是让模块搬迁存档的命令。
- 无有效存档声明的旧模块保持兼容，不能对所有 `RUNTIME_MODULE` 一律开放存档管理。

### 7.2 路径边界与文件操作

- `directory` 必须是非空相对目录，最多 256 个 UTF-16 code unit、8 层；仅使用 `/` 分隔，拒绝绝对路径、盘符/URI、反斜杠、空段、`.`、`..`、通配符、控制字符及首尾 `/`。路径大小写保留，不 URL 解码，不接受游戏根本身。
- 用统一 core 解析器将启动游戏根与相对目录拼接，验证规范化目标严格位于规范化游戏根之内。不能仅用字符串前缀判定；游戏根的系统存储别名按 `SavePathSafety` 的 trusted root 规则解析，根以下路径和存档树中的符号链接一律拒绝，不跟随链接跨出范围，复用并补足现有约束。
- 管理范围是该子目录树内的普通文件，不扫描、打包、覆盖或删除游戏根其它内容。所有导入导出、删除、版本快照、回滚与同步入口共用同一解析器和路径校验，写入/替换前再次核对绑定、声明指纹和真实目录；校验失败返回已有类型化错误协议。
- 事务暂存/备份等可能位于存档目录的相邻位置，须沿用已有事务恢复机制，并核对其路径仍在游戏根内、与游戏资源/其它存档目录不冲突；不能只校验最终目标而放任暂存路径越界或覆盖现有数据。
- 当前固定的 `<dir>.import_staging` / `<dir>.import_backup` 不能仅凭名称被认定为本 App 事务。为第三方目录补可验证的事务所有权记录（App 私有持久化记录中的游戏/模块/规范目标目录、transaction token 与阶段），开始前先验证相邻路径；已存在但无匹配记录或无法证明所有权时，导入、恢复、删除、清理均返回目录不可用/冲突的类型化失败，原路径保持原样，不恢复、不覆盖、不递归删除。为新事务先持久化所有权记录再创建事务路径，异常恢复同样复核记录与路径，不把一般游戏资源猜作旧事务。扩展须覆盖现有恢复与 `transactionSiblings` 清理调用点，不能只保护导入开始入口。
- 不预创建存档目录。权限足够、游戏根可访问且路径安全，但目标尚不存在时视为空存档；不能据此当作已有本地数据而自动覆盖云端。手动导入或已确认的恢复操作按现有事务流程创建目标，启动和纯浏览不创建。
- 目录存在却是文件、不可读、无足够权限、存储卷离线或目录无法可靠解析，均是存档暂不可用，不能当作空存档。只支持主 App 实际能够执行现有 File 事务的目录；不为本次扩展伪造 SAF 或模块私有目录访问能力，也不为浏览主动请求所有文件访问。
- 首版不配置扩展名过滤，也不将游戏根作为存档目录。若模块混放资源或存档位于模块私有目录，本能力不适用；模块需先提供独立的游戏内存档子目录。

### 7.3 统一存档入口、能力与同步

- 抽屉中的「存档管理」根据有效 saves 能力显示，独立于「引擎设置」。存档页沿用现有 `SaveManagementActivity`、路径展示、导入/导出/删除、版本记录与恢复入口；路径不再硬编码排除所有第三方模块。
- 把 `supportsFileSaves(engine)`、`supportsManagedSave(engine)` 和 UI 的引擎级判断扩展为可消费游戏及模块能力快照的 core 门面；保留既有引擎行为，UI 不解析模块 JSON 或自行判路径。
- 能力判断区分「明确不支持」「支持但存储暂不可用」「发现状态未知」。查询失败不等于不支持；有最近成功快照时保留能力与身份占用，但文件操作必须重新确认当前绑定和目录，无法确认就报不可用；无成功快照时不进行文件操作或自动同步，不把未知状态当空存档。已绑定模块包名可用时，即使冷启动发现失败也先计算模块命名空间并保守参加云端身份冲突占位；不能把暂停文件传输写成从冲突分组中直接跳过。
- 声明有效且目录可用时，纳入现有单游戏和整库 WebDAV 同步；只有明确无接口的模块才在云端身份分组前排除。支持但暂不可用的游戏仍保留云端身份占用，避免同名游戏覆盖已有云端存档。
- 云端身份的引擎命名空间须纳入模块包名，避免不同第三方模块同名游戏碰撞；用户编辑的云端游戏标识也不能绕过模块命名空间。沿用现有标识编辑和身份冲突处理，不自动合并。当前 `SaveSyncService` 的 `remoteKey()` 和 `RemoteSaveGame` 都使用 `engine.name`，须共同改为复用一个模块感知的命名空间解析结果，并同步核对冲突分组、checkpoint 与版本快照，不能只改 UI 可见性或其中一处 hash。
- 文件操作锁沿用规范化真实存档目录标识，并检查同目录、父子目录的重叠；两个 URI 实际共享同一目录时必须共用锁与活动标记，不能只按包名/游戏 URI 加锁。版本历史仍沿用既有游戏身份，快照携带实际目录/声明身份，防止恢复到已经变化的目标。
- 模块更新改变存档声明、游戏绑定或实际目录时，不搬迁、不删除旧目录，不自动向新目录回放旧版本/云端存档；将旧活动会话和待处理同步的目录身份保留，提示用户确认新路径并沿用现有手动选择/恢复流程。首次接入云端和目录变更均不能把「本地空」自动解释为删除远端。

### 7.4 外置运行标记与一致性

- 第三方模块是独立 APK，不能凭主 App 回到前台、Activity 返回或 `Dispatched` 判定游戏已退出。复用 Ren’Py/YU-RIS 的持久化外置启动标记和显式退出确认，扩展 `requiresExternalSaveExitConfirmation` 及全部调用方。
- 启动前先准备并校验当前模块能力快照，再进入 `SaveSyncRuntime.launchAdmission` 和既有目录门禁；最终发 Intent 使用同一包名、声明指纹与目录基准，发生变化重新准入，避免当前 launcher 在准入之后刷新模块而造成目录快照不一致。
- 有效 saves 模块的文件访问/启动准入不随 WebDAV 开关关闭：即使不启用云同步，也先解析真实目录，取得与手动文件操作一致的 active/mutation 门禁，再登记外置运行标记并启动。当前 `optionalSaveSyncLaunchAdmission` 在 WebDAV 关闭时返回 Disabled、跳过目录解析的路径须针对该能力调整，不能只在后续登记无目录 key 的标记。
- 启动交棒前登记运行标记，交棒成功保留、明确启动失败撤销；标记记录游戏 URI、模块包名、声明/真实目录身份与启动 token。即使 WebDAV 关闭，手动文件操作也必须受到运行标记保护；重启主 App 后仍需确认外置游戏已退出。
- 导入、导出、删除、版本创建/恢复和同步都通过共享的活动/修改门禁，并在未确认退出时拒绝执行。不能只扩展当前 `withManualSaveAccess` 中 Ren’Py 的分支而漏掉版本快照、同步枚举与其它直接读写入口。
- 模块禁用、卸载、游戏降级、发现失败或声明变更均不能自动清除已交棒会话的保护；用户确认退出后才能释放对应旧目录保护。旧标记的退出确认通过已登记身份提供，不依赖当前引擎仍为 `RUNTIME_MODULE` 或模块当前仍能被发现，避免降级后再也无法确认。只有声明有效时登记新会话，不给无存档能力模块增加运行限制。
- 用户必须能到达旧会话确认：游戏仍在库时，即使正常存档入口因能力消失而不可用，抽屉仍根据持久化待确认标记提供「确认游戏已退出」动作；游戏已移除时，在现有存档同步页面的待处理会话区域保留同一确认动作，不新增全局配置项。确认页显示标记中的模块及旧目录身份，并在提交时核对当前启动 token；不能拿过期 Intent 或一次确认解除之后新启动的保护。该入口只释放经确认的会话，不开放失效模块的文件操作。

## 9. 验证与完成标准

### 9.1 自动检查

- JVM：描述缺失/未知版本/非法类型/重复 key/边界长度/超限；scan、settings、saves 三块独立容错。
- JVM：false、0、空字符串不当成缺失；非法覆盖回退；不同游戏/不同包隔离；声明新增、删除、改类型、枚举变化。
- 存储：覆盖 JSON 分区往返、保存保留其它字段、恢复仅清当前模块、备份恢复与游戏移除清理策略。
- 启动：无能力不带 extra，有能力下发完整有效配置；协议常量与原 v1 参数兼容；读取/容量失败不误报交棒。
- 回归：现有 runtime 扫描、绑定降级、旧模块启动，Ren’Py/RGSS/Ruffle 的设置与启动测试。
- 存档路径：空/根/绝对路径、盘符、URI、`.`/`..`、通配符、大小写、控制字符、过深/过长路径、前缀相同的兄弟目录、符号链接/运行期间换链；事务暂存路径不能碰其它资源。
- 存档能力：仅 saves、仅 settings、两者都有、两者都无，以及各块独立容错；分别测试 saves 非对象、version 缺失/未知/非整数、directory 缺失/非字符串/空/非法/超长时仍保留有效 scan/settings；支持但不可用与空存档/不支持区分。
- 文件回归：导入、导出、删除、版本创建/恢复只处理声明目录；损坏 ZIP、路径越界、不可读、权限不足、存储离线、空间不足与事务中断恢复。预置同名 staging/backup 游戏资源、所有权记录缺失/不匹配时必须失败且保留原文件；本 App 事务的各中断阶段可恢复。其它游戏资源保持原样。
- 同步回归：跨模块同名游戏命名空间、同目录/父子目录锁、暂不可用游戏身份占用、本地尚无存档、目录变更不自动迁移/覆盖、旧版本不能误还原到新目标。
- 外置生命周期：WebDAV 开/关、启动成功/失败、重复启动、返回主 App、主进程重启、模块禁用/卸载后退出确认，以及与导入/删除/版本操作并发。
- 编译与静态门禁：相关 `:app:testDebugUnitTest`、`:app:assembleDebug`、`:app:lintDebug`，以及 `python tools/check-hardcoded-ui-strings.py`、`python tools/check-motion-boundaries.py`、`git diff --check`。记录实际结果和既有失败，不宣称全仓通过。

### 9.2 设备验收

以独立示例 APK 声明四类设置并显示收到的 JSON，不将测试接收页当作真实游戏兼容性验收。

- 手机/平板、横竖屏、浅色/深色/两种玻璃外观；普通/增强动效及系统关闭动画；截图不纳入仓库。
- 从首页与游戏库抽屉进入，修改、保存、重进、启动收到一致值；取消未保存修改不落盘；恢复默认后保存再启动收到默认值。
- 两个游戏独立配置；两个模块同名字段独立；模块更新改变默认值时未覆盖字段跟随变化，显式覆盖保持。
- 在页面打开期间卸载、禁用、更新模块，以及发现查询失败，验证不会误存旧描述或清空其它设置。
- 后台恢复、旋转、进程重建、重复保存与返回确认，不丢草稿、不误报保存。
- 示例模块在声明目录写入真实测试存档，完成导出→删除→导入、版本恢复及 WebDAV 双向同步，验证文件内容与游戏根其它资源未变；该测试证明接入链路，不代表商业游戏兼容性。
- 外置游戏未确认退出时拒绝文件操作；关闭 WebDAV、回到主 App 或重启主进程都不能绕过保护。目录尚未创建、权限缺失、可移动存储离线和模块更新后路径变化均需实际验证。
