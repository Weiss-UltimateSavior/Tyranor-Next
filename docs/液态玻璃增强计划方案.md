# 液态玻璃增强计划方案

> 目标：在应用设置「圆角液态玻璃导航」开关之下新增子项「**液态玻璃增强**」（默认隐藏、默认关闭），
> 打开后底栏改用 Legado 三层采样 + 折射透镜 + 按压拖动的高保真液态玻璃实现；关闭时保持现有
> 圆角液态玻璃底栏**行为与画面完全不变**。
>
> 依据：《Tyranor-Next × Legado：液态玻璃底栏对比与高保真复刻方案》v1.1（下称「分析报告」）。
> 实现底座：Tyranor-Next `origin/main` @ `8ff6d30`（分析报告核查基线为 `0f49e38`，
> 其后官方陆续合入圆角常量统一、玻璃顶栏修复与重构、Ren'Py 模块设置；本方案已在最新底座上完成 rebase）。

---

## 1. 决策记录

| 决策点 | 结论 |
|---|---|
| 新选项位置 | 应用设置 → 「圆角液态玻璃导航」同一张 MiuixCard 内，作为其下子项 |
| 显隐规则 | **只要父开关「圆角液态玻璃导航」打开，子项就出现**（不限外观风格，默认隐藏）；父开关关闭时子项复位为关闭并持久化 |
| 默认值 | 关闭。默认画面与改造前完全一致 |
| 生效条件 | `nav_style == liquid_glass` **且** `liquid_glass_enhance == true`（任意外观风格） |
| 复刻路线 | 报告路线 **B**：沿用项目现有 Backdrop **1.0.2**（已含 `lens` / `CombinedBackdrop` / `InnerShadow`），按参考实现的光学参数与交互设计**独立实现**（见 §3.1 版权说明） |
| 轮廓 | 胶囊（`RoundedCornerShape(50%)`）替代 capsule 库的 `ContinuousCapsule`（见 §6 差异 D1） |
| 四项适配 | 保留 Tyranor 四项业务；按参考单槽宽度 76dp 居中收窄（报告 §8.1 / §8.5） |
| 取消语义 | **取消不提交**，回到当前选中项（报告 §8.1「正式产品建议」，与源实现不同，见 §6 差异 D3） |
| 宿主转场 | **仅增强档**在转场期间接受新目标（重定向）；默认路径保留原 `isRunning` 守卫（报告 §8.7） |
| 震动 / 彩虹色散 | 不新增（源实现无此调用，报告 §6.2 / §6.5） |

## 2. 开关模型

### 2.1 `core/settings/AppSettingsStore.kt`

| 项 | 内容 |
|---|---|
| key | `liquid_glass_enhance`（Boolean，独立 `app_settings` prefs） |
| 内存态 | `liquidGlassEnhanceState: MutableStateFlow<Boolean>`（默认 `false`） |
| 读取 | `getLiquidGlassEnhance(c)`；`initNavStyle(c)` 一并加载（幂等） |
| 写入 | `setLiquidGlassEnhance(c, enabled)` |
| 复位 | `setNavStyle(c, style)` 在 `style != NAV_STYLE_LIQUID_GLASS` 时，把 `nav_style` 与 `liquid_glass_enhance=false` 写在**同一次 `edit()` 事务**里 |

复位在写入侧一次事务完成；读取侧 `initNavStyle()` 还会再归一化一次
（`liquid_glass_enhance && nav_style == liquid_glass`），并在不一致时把归一化结果**写回磁盘**。
两道保险合起来保证「持久化值」与「界面可见状态」始终一致：隐藏项不会残留开启态，
用户下次打开父开关时不会被“静默”改变外观。

### 2.2 设置页 `ui/settings/AppSettingsActivity.kt`

```kotlin
if (liquidGlass) {                       // 父开关打开才出现（默认隐藏）
    SwitchPreference(
        title = R.string.settings_liquid_glass_enhance,
        summary = R.string.settings_liquid_glass_enhance_summary,
        checked = liquidGlassEnhance,
        onCheckedChange = { AppSettingsStore.setLiquidGlassEnhance(ctx, it) },
    )
}
```

文案（中 / 英 / 日三语齐全）：

| key | 简体中文 | English | 日本語 |
|---|---|---|---|
| `settings_liquid_glass_enhance` | 液态玻璃增强 | Liquid glass enhancement | リキッドグラス強化 |
| `settings_liquid_glass_enhance_summary` | 折射透镜与按压拖动手感（Android 13 及以上完整生效） | Refraction lens with press and drag response (full effect on Android 13+) | 屈折レンズと押下・ドラッグ操作（Android 13 以上で完全に有効） |

**版权与实现方式（重要）**：本项目为 **GPL-2.0-only**，而参考项目
`HapeLee/legado-with-MD3`（其 `FloatingBottomBar.kt` 又自述衍生自 `weishu/KernelSU`）为 **GPL-3.0**，
两者不兼容。因此本方案**不复制上游代码表达**：算法、参数取值、渲染分层顺序属于不受版权保护的
设计要素，代码本身由本项目独立编写，**7 个实现文件全部为独立实现**，不保留 GPL-3.0 衍生署名：
- 手势识别器用单层状态机重写（上游是三段回调链）；
- 运动控制器**重新架构**为「一个帧循环 + 五个自写弹簧积分器」，不使用 `Animatable` /
  `MutatorMutex` / `snapshotFlow` / `VelocityTracker`，松手吸附与收材质是循环内的普通条件；
- 按压光斑的 AGSL 着色器为自写表达式（上游同位置为逐字节相同的移植版）；
- 栏体组件拆分为多个私有 Composable，构图与注释结构均与上游不同。

参考来源记于致谢：`legado-with-MD3` @ `fb01a76ebbbca41423e2c4c00080cc0861239fbd`。

## 4. 渲染链与参数

### 4.1 三层采样（报告 §6.1）

```text
页面内容 ─────────────────────────────→ pageBackdrop（MainScreen 录制）
    │
    ├─ A 可见栏：vibrancy → blur(8dp) → lens(24dp,24dp) → 表面色 40% → 边缘高光（无投影）→ 清晰图标
    │
    ├─ B 隐藏副本：clearAndSetSemantics + alpha(0f) + layerBackdrop(tabsBackdrop)
    │        内部：图标按 1→1.2 放大 + 强调色 tint
    │              └────────────────────→ tabsBackdrop
    │
    └─ C 移动透镜：CombinedBackdrop(page, tabs)
                   lens(10dp×p, 14dp×p, depth=true) + 内阴影 + 静止/按压覆盖 + 速度形变
```

Modifier 顺序按报告 §8.4 固定，不可调换（顺序错误会导致空采样、重影或裁切）。

### 4.2 参数（`GlassBottomBarSpec.Default`，全部为源默认档）

| 参数 | 值 | 来源 |
|---|---|---|
| 栏高 / 内边距 / 透镜高 | 64dp / 4dp / 56dp | 报告 §6.3 |
| 单槽参考宽 / 宿主左右留白 | 76dp / 16dp | 报告 §6.3 / §8.5 |
| blur / 表面 alpha / 栏体 lens | 8dp / 0.40 / 24dp | 报告 §6.3（用户确认默认档） |
| 透镜 lens（按压） | 10dp×p 高、14dp×p 位移、`depthEffect=true` | 报告 §6.3 |
| 按压缩放 / 副本图标放大 | 78/56 ≈ 1.3929 / 1 → 1.2 | 报告 §6.3 |
| 整栏按压缩放 / 横向跟随 | `1 + 16dp/栏宽` / ±4dp（EaseOut 映射） | 报告 §6.3 / §6.4 |
| 位置 spring | `1f / 1000f / 0.001f` | 报告 §6.3 |
| 速度 spring | `0.5f / 300f / 0.01f` | 报告 §6.3 |
| 按压进度 spring | `1f / 1000f / 0.001f` | 报告 §6.3 |
| X / Y 缩放 spring | `0.6f / 250f`、`0.7f / 250f` | 报告 §6.3 |

### 4.3 交互（报告 §6.5 / §8.6）

- 按住透镜**立即**进入按压（`awaitFirstDown` 后即 press），无长按计时、无 touch slop 等待。
- 拖动按 `dx / tabWidth` 累加目标索引，LTR/RTL 方向翻转，索引夹取在 `[0, N−1]`。
- 跟随位置使用源 spring，速度取**动画位置的采样速度**（非手指 px/s）。
- 松手：`round(target)` **吸附到整数槽位** → 提交切页 → 材质回落（位置先靠近目标再收）。
- 取消：**不提交**，透镜回到当前选中项。
- 快速重抓：控制器带会话编号，上一轮未完成的释放不会把新按下的透镜缩回去。

## 5. 降级策略（报告 §8.8）

| 平台 | 行为 |
|---|---|
| API 33+ | 完整：实时模糊 + `lens` 折射 + `depthEffect` + 交互高光 shader |
| API 31–32 | 仅实时模糊 + 栏体透镜**不生效**（Backdrop 1.0.2 的 `lens` 在 < API 33 直接早退，栏体 lens 与透镜折射都是 no-op）；`Highlight` / `Shadow` / `InnerShadow` 由调用方在能力不足时传 `null`（不走无谓的离屏层）；`onDrawSurface` 仍绘制，因此选中态用主题色半透明胶囊兜底。与报告 §8.8「模糊 + 非折射选中反馈」一致 |
| API 26–30 | 无模糊：不透明实底 + 主题色半透明选中胶囊 |

能力由 `GlassBottomBarCapabilities.current` 单独表达，用户开关只决定「是否启用」，不参与能力判定。
降级档**不计入**高保真验收，也不描述为「已实现完整折射」。

## 6. 与源实现的显式差异（报告要求逐项记录）

| 编号 | 差异 | 原因 |
|---|---|---|
| D1 | 轮廓用 `theme/AppShapes.kt` 的 `AppNavCapsuleShape`（`RoundedCornerShape(50%)`）而非 capsule 库 `ContinuousCapsule` | 避免为新轮廓引入依赖：Backdrop 1.0.2 的 `lens` 只接受 `CornerBasedShape`，`ContinuousCapsule` 属 2.0.1 一档（其 lens 另有一条 `RoundedRectangularShape` 分支）。两者是不同几何类，本方案**不主张**像素等价，只主张胶囊几何下差异收敛（未实测） |
| D2 | 主题适配器放在 `ui/common/glass/` 而非报告建议的 `theme/` | 项目 `theme/` 当前不依赖 `ui/`，保持 `ui → theme` 依赖方向（AGENT.md 三层架构纪律） |
| D3 | 取消不提交（源实现 Cancel 与 End 调同一回调，可能提交） | 报告 §8.1「正式产品建议取消不提交」。**代价**：源实现取消时（无模糊档）仍会绘制中性 10% 覆盖，本实现改为回原项 + 主题色胶囊 |
| D4 | 速度归一化跨度与释放阈值固定为五项参考值（4 / 0.10） | 报告 §8.5「四项适配参数」，用于保持参考手感；**不得**表述为源码未改 |
| D5 | 增加了会话编号丢弃过期释放流程 | 报告 §8.6 第 5 条要求正式版本增加 Job / 会话管理 |
| D6 | 首次组合不播放「按下再回弹」过渡 | 源实现的 `LaunchedEffect` 在启动时会触发一次按压动画；Tyranor 启动画面不保留该脉冲 |
| D7 | 无折射能力时用主题色胶囊做选中兜底（源实现该档仍画中性 10% 覆盖） | 10% 中性覆盖在深色/复杂背景上不足以表达选中态，低版本需要可读的选中反馈 |
| D8 | 栏体宽度按窗口宽度夹取 | 报告 §9 窄屏风险：76dp 单槽在极窄屏可能放不下 |
| D9 | 拖动释放后不再重复播放一次按压脉冲 | 源实现 `onDragStopped` 已 `animateToValue(target)`，宿主回传 `selectedIndex` 时其 `LaunchedEffect` 会再触发一次；本实现按 `targetValue` 判重跳过第二次（影响 V02/V06 的像素阶段） |
| D10 | 依赖停留在 Backdrop **1.0.2**（源为 2.0.1）且不引入 capsule 库 | 报告 §7.2 路线 B。已核对：`Highlight` / `Shadow` / `InnerShadow` 数据默认值两版一致，折射 shader 字符串未变（唯一差异 `half4(1.0)` → `color`，白色默认下等价），残余像素风险集中在轮廓几何（见 D1） |
| D11 | **栏体不画外部投影**（`shadow = null`） | 源实现投影为浅色 10% / 深色 20% 黑、24dp 模糊、向下偏移 4dp，是本项目原液态玻璃栏（`Shadow.Default.copy(alpha = 0.8f)`，等效 8%）的 2.5 倍；在深色渐变背景上会形成一圈比栏体更大的暗色圆角轮廓（观感上像底栏下面还压着一层）。用户确认去掉。**注意**：移动透镜按压时（`pressProgress > 0`）的阴影与内阴影保留，静止时为 0，不产生常驻暗层 |
| D12 | **栏体边缘高光降到「微浅」**：`spec.barHighlightAlpha = 0.18`（约 9% 白） | 源值为 `Highlight.Default.copy(alpha = 1f)`，即 50% 白 + `BlendMode.Plus`；在栏体两端圆弧处形成一条明显亮边，横截面观感为「深（栏外）→ 浅（亮边）→ 深（栏内）」。用户要求改为「深 → 微浅 → 深」。移动透镜按压时的高光仍按 `pressProgress` 走源值（瞬时，非法常驻） |
| D13 | **采样副本行不做随按压变化的折射**（只保留 vibrancy + blur） | Backdrop 的 `lens()` 会改变采样边距，边距决定离屏图层尺寸；若其强度随按压进度变化，副本行图层会**逐帧改变尺寸**（重分配渲染目标）。折射交给移动透镜完成，静止观感不变 |
| D14 | 按压光斑由**透镜的按压进度驱动**，不再单独维护跟手位置动画与更慢的一条弹簧 | 原方案的位置动画在其装配方式下并未参与绘制（每帧多一次协程却无视觉产出）；共用同一弹簧后亮度与体积同步，节奏更一致 |

此外，报告 §8.7 的宿主修复已实施：增强档下 `MainScreen.selectPage()` 不再因转场 `isRunning` 丢弃输入，
改为接受新目标由 `updateTransition` 从当前显示状态重定向；**默认路径保留原守卫**，
因此本方案对未开启该选项的用户没有任何行为变更。

### 9.1 测试用包名（调试包不与原版同包名）

调试包必须与原版 `com.tyranor.next` 不同包名，否则无法与原版共存安装。
本项目已有现成开关 `TYRANOR_APPLICATION_ID`（`app/build.gradle.kts:92`，读取顺序 env →
`local.properties` → Gradle property），因此**不改动入库的构建脚本**，只在本机 `local.properties`
（已 gitignore）写入：

```properties
TYRANOR_APPLICATION_ID=com.tyranor.next.test
```

产物包名为 `com.tyranor.next.test`，可与原版同时安装；`namespace` 仍为 `com.tyranor.next`，
`R` / `BuildConfig` 与源码包路径不受影响，Manifest 中的
`${applicationId}.fileprovider`、`${applicationId}.androidx-startup` 会随包名自动改写。

若希望**所有** debug 变体永久使用测试包名，应在 `app/build.gradle.kts` 的 `buildTypes` 中加
`debug { applicationIdSuffix = ".test" }`（本次未采用：发版流程与 CI 不在本方案改动范围内）。
