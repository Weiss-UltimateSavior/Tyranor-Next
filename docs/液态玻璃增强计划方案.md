# 液态玻璃增强计划方案

> 目标：在应用设置新增下拉项「**导航栏样式**」，三选一 —— 默认 / **液态玻璃 · 经典** /
> **液态玻璃 · 透镜**（后者即本方案的高保真实现：三层采样 + 折射透镜 + 按压拖动，仅 Android 13+
> 提供，低版本归一化为经典档）。选择「默认」或「经典」时，既有实现**行为与画面完全不变**。
>
> 依据：《Tyranor-Next × Legado：液态玻璃底栏对比与高保真复刻方案》v1.1（下称「分析报告」）。
> 实现底座：Tyranor-Next `origin/main` @ `e9436f0`（分支已 rebase 到该提交）（分析报告核查基线为 `0f49e38`，
> 其后官方陆续合入圆角常量统一、玻璃顶栏修复与重构、Ren'Py 模块设置；本方案已在最新底座上完成 rebase）。

---

## 1. 决策记录

| 决策点 | 结论 |
|---|---|
| 新选项位置 | 与普通档合并为**同一个下拉 item**「导航栏样式」：默认 / 液态玻璃 · 经典 / 液态玻璃 · 透镜 三选一 |
| 显隐规则 | **Android 13 以下的设备不提供「液态玻璃 · 透镜」选项**（列表里不出现）；即使从新版备份恢复数据，读取时也会归一化为普通档 |
| 默认值 | 关闭。默认画面与改造前完全一致 |
| 生效条件 | `nav_style == liquid_glass_enhanced`（任意外观风格；低于 Android 13 时归一化为 `liquid_glass`） |
| 复刻路线 | 报告路线 **B**：沿用项目现有 Backdrop **1.0.2**（已含 `lens` / `CombinedBackdrop` / `InnerShadow`），按参考实现的光学参数与交互设计**独立实现**（见 §3.1 版权说明） |
| 轮廓 | 胶囊（`RoundedCornerShape(50%)`）替代 capsule 库的 `ContinuousCapsule`（见 §6 差异 D1） |
| 四项适配 | 保留 Tyranor 四项业务；手机按参考单槽宽度 76dp 居中收窄，平板/横屏（≥600dp）拉伸铺满，与原版液态玻璃导航一致（见 §6 D18） |
| 取消语义 | **取消不提交**，回到当前选中项（报告 §8.1「正式产品建议」，与源实现不同，见 §6 差异 D3） |
| 宿主转场 | **仅透镜档**在转场期间接受新目标（重定向）；默认路径保留原 `isRunning` 守卫（报告 §8.7） |
| 震动 | **新增触觉反馈**（源实现无此调用；用户要求，见 §6 D16），用 `performHapticFeedback`，无马达不触发 |
| 彩虹色散 | 不新增（源实现未启用 `chromaticAberration`，报告 §6.2） |

## 2. 开关模型

### 2.1 `core/settings/AppSettingsStore.kt`

| 项 | 内容 |
|---|---|
| key | `nav_style`（String，独立 `app_settings` prefs），三态取值 |
| 取值 | `default`（Material3 导航栏）/ `liquid_glass`（液态玻璃）/ `liquid_glass_enhanced`（液态玻璃 · 透镜） |
| 内存态 | `navStyleState: MutableStateFlow<String>`（默认 `default`） |
| 读取 | `getNavStyle(c)`；`initNavStyle(c)` 首次组合时加载（幂等） |
| 写入 | `setNavStyle(c, style)`（内部先归一化再落盘并广播） |
| 归一化 | `normalizeNavStyle(stored, enhancedSupported)`：未知值→`default`；透镜档在 Android 13 以下→`liquid_glass`（纯函数，有单测） |
| 迁移 | 早期实现把透镜档存成独立布尔 `liquid_glass_enhance`；`initNavStyle` 一次性升级为 `liquid_glass_enhanced` 并删除旧键 |

单项三态取代了「父开关 + 子开关」：不存在「父项已关、子项仍为 true」的隐藏态，
也就不需要任何复位语义；旧数据由迁移函数兜住。

**说明文案只保留「安卓版本提醒」**：下拉下方的摘要不再描述界面形态，只在需要的档位提示版本要求
（经典档 Android 12+、透镜档 Android 13+）；默认档不加摘要，保持界面简洁。

### 2.2 设置页 `ui/settings/AppSettingsActivity.kt`

```kotlin
OverlayDropdownPreference(               // 非布尔选择，按 AGENT.md 用下拉而非开关
    title = stringResource(R.string.settings_nav_bar_title),   // 底部导航栏
    summary = <当前档位的说明>,
    items = listOf(默认, 液态玻璃 · 经典, [液态玻璃 · 透镜]),            // 增强项仅在 Android 13+ 出现
    selectedIndex = navStyleIndex,
    onSelectedIndexChange = { AppSettingsStore.setNavStyle(ctx, style) },
)
```

| `settings_nav_bar_default` | 默认 | Default | デフォルト |
| `settings_nav_bar_liquid_glass` | 液态玻璃 · 经典（原版小圆角方形栏 + 模糊） | Liquid glass · Classic | リキッドグラス · クラシック |

**版权与实现方式（重要）**：本项目为 **GPL-2.0-only**，而参考项目
`HapeLee/legado-with-MD3`（其 `FloatingBottomBar.kt` 又自述衍生自 `weishu/KernelSU`）为 **GPL-3.0**，
两者不兼容。因此本方案**不复制上游代码表达**：算法、参数取值、渲染分层顺序属于不受版权保护的
设计要素，代码本身由本项目独立编写，**7 个实现文件全部为独立实现**，不保留 GPL-3.0 衍生署名：
- 手势识别器用单层状态机重写（上游是三段回调链）；
- 运动控制器**重新架构**为「一个帧循环 + 五个自写弹簧积分器」，不使用 `Animatable` /
  `MutatorMutex` / `snapshotFlow` / `VelocityTracker`，松手吸附与收材质是循环内的普通条件；
- 按压光斑的 AGSL 着色器为自写表达式（上游同位置为逐字节相同的移植版）；
- 栏体组件拆分为多个私有 Composable，构图与注释结构均与上游不同。

参考来源记于致谢：`legado-with-MD3` @ `fb01a76ebbbca41423e2c4c00080cc0861239fbd`。

## 4. 渲染链与参数

### 4.1 三层采样（报告 §6.1）

```text
页面内容 ─────────────────────────────→ pageBackdrop（MainScreen 录制）
    │
    ├─ A 可见栏：ColorMatrix 色彩滤镜 → blur(3dp) → lens(12dp,8dp, 含色散) → 表面色 34%
    │              → 边缘高光 + 浅色档内阴影 → 清晰图标（不做速度形变，见 D29）
    │
    ├─ B 隐藏副本：clearAndSetSemantics + alpha(0f) + layerBackdrop(tabsBackdrop)
    │        内部：图标按 1→1.2 放大 + 强调色 tint
    │              └────────────────────→ tabsBackdrop
    │
    └─ C 移动透镜：CombinedBackdrop(page, tabs)
                   lens(静止↔按压插值, depthEffect=false, chromaticAberration=true)
                   + 内阴影 + 静止/按压覆盖（**不做速度形变**，见 §6 D29）
```

Modifier 顺序按报告 §8.4 固定，不可调换（顺序错误会导致空采样、重影或裁切）。

### 4.2 参数（`GlassBottomBarSpec.Default`，全部为源默认档）

| 参数 | 值 | 来源 |

| 栏高 / 内边距 / 透镜高 | 64dp / 4dp / 56dp | 报告 §6.3 |
| 单槽参考宽 / 宿主左右留白 | 76dp / 16dp | 报告 §6.3 / §8.5 |
| blur / 表面 alpha / 栏体 lens | 浅深均 3dp / 0.34 / 12dp×8dp（**含色散**） | 报告 §6.3 起点经实测下调，见 D28/D30 |
| 移动透镜 lens（静止 → 按压） | 6dp×8dp → 10dp×12dp、`chromaticAberration = true`、`depthEffect = false` | 见 D28；Backdrop 1.0.2 的第三位参数是 `depthEffect`，旧代码在此写 `true` 并没有开色散 |
| 按压缩放（X = Y）/ 副本图标放大 | 78/56 ≈ 1.3929 两轴相同 / 1 → 1.2 | 用户要求「只做按压放大、左右一致」，见 D29 |
| 整栏按压缩放 / 横向跟随 | `1 + 16dp/栏宽` / ±4dp（EaseOut 映射） | 报告 §6.3 / §6.4 |

| 弹簧收敛阈值 | `visibilityThreshold = 0.001` | 报告 §6.3 |

### 4.3 交互（报告 §6.5 / §8.6）

- 按下**任意位置**：同刻一次短震（语义激活另有单独一次）。
- **轻点**（未到抓取阈值且未拖动）→ 完全走 PR81 的单相路径：`settleAt(pulse = true)`，
  起胀与滑行同帧开始；**按住 ≥ `grabDelayMillis`** 或**越过平台 touch slop 开始拖动**时，
  才把滑块抓到手指出（见 §6 D27）。
- 拖动按**指针绝对 x** 经 `pointerXToIndex` 折成连续索引（`dx / tabWidth` 等价），LTR/RTL 方向翻转，索引夹取在 `[0, N−1]`。
- 跟随位置使用源 spring；**MOVE 使用绝对目标**（`updatePressTarget`），不累加位移。
- 松手：`round(target)` **吸附到整数槽位** → 提交切页 → 材质回落（位置先靠近目标再收）。
- 取消：**不提交**，透镜回到当前选中项。
- 点击：**按下即给**一次短震动，没有到位补震，也没有松手补震（同一次物理会话只震一次，见 D16）。
- 快速重抓：下一次按下直接清掉上一轮未完成的收材质意图（`shrinkWhenSettled`），不存在挂起的释放流程。

> 触觉反馈用 `View.performHapticFeedback`，不需要 `VIBRATE` 权限。参考实现没有震动，
> 这一条是本项目按用户要求新增（D16）。

## 5. 降级策略（报告 §8.8）

| 平台 | 行为 |
|---|---|
| API 33+ | 完整：实时模糊 + `lens` 折射 + `depthEffect` + 交互高光 shader |
| API 31–32 | 仅实时模糊 + 栏体透镜**不生效**（Backdrop 1.0.2 的 `lens` 在 < API 33 直接早退，栏体 lens 与透镜折射都是 no-op）；`Highlight` / `Shadow` / `InnerShadow` 由调用方在能力不足时传 `null`（不走无谓的离屏层）；`onDrawSurface` 仍绘制，因此选中态用主题色半透明胶囊兜底。与报告 §8.8「模糊 + 非折射选中反馈」一致 |
| API 26–30 | 无模糊：不透明实底 + 主题色半透明选中胶囊 |

能力由 `GlassBottomBarCapabilities.current` 单独表达，用户开关只决定「是否启用」，不参与能力判定。

**注意（评审后修正）**：设置里「液态玻璃 · 透镜」只在 **Android 13+** 出现，且读取时会归一化，
所以在本应用里上表的 31–32 / 26–30 两档**实际不可达**——它们只是组件层的能力分支（组件契约要求
能力可降级，便于将来复用到更低门槛的场景）。因此 V13「低版本降级分支」无法在应用内验证，
也不得在 PR 里宣称已覆盖。

## 6. 与源实现的显式差异（报告要求逐项记录）

| 编号 | 差异 | 原因 |
|---|---|---|
| D1 | 轮廓用 `theme/AppShapes.kt` 的 `AppNavCapsuleShape`（`RoundedCornerShape(50%)`）而非 capsule 库 `ContinuousCapsule` | 避免为新轮廓引入依赖：Backdrop 1.0.2 的 `lens` 只接受 `CornerBasedShape`，`ContinuousCapsule` 属 2.0.1 一档（其 lens 另有一条 `RoundedRectangularShape` 分支）。两者是不同几何类，本方案**不主张**像素等价，只主张胶囊几何下差异收敛（未实测） |
| D2 | 主题适配器放在 `ui/common/glass/` 而非报告建议的 `theme/` | 项目 `theme/` 当前不依赖 `ui/`，保持 `ui → theme` 依赖方向（AGENT.md 三层架构纪律） |
| D3 | 取消不提交（源实现 Cancel 与 End 调同一回调，可能提交） | 报告 §8.1「正式产品建议取消不提交」。**代价**：源实现取消时（无模糊档）仍会绘制中性 10% 覆盖，本实现改为回原项 + 主题色胶囊 |
| D4 | 释放判定阈值固定为参考值 `0.10`（速度归一化跨度已随 D29 一并删除，不再是适配参数） | 报告 §8.5「四项适配参数」，用于保持参考手感 |
| D5 | 用「**松手才收材质**」的状态标记取代挂起的释放流程 | 报告 §8.6 第 5 条要求正式版本处理「旧释放抢回新透镜」。本实现里 `beginPress()` 直接清掉 `shrinkWhenSettled`，不再存在旧协程把新按压缩回去的窗口（原方案用会话编号做到这一点，现已不需要） |

### 9.1 测试用包名（调试包不与原版同包名）

调试包必须与原版 `com.tyranor.next` 不同包名，否则无法与原版共存安装。
本项目已有现成开关 `TYRANOR_APPLICATION_ID`（`app/build.gradle.kts:92`，读取顺序 env →
`local.properties` → Gradle property），因此**不改动入库的构建脚本**，只在本机 `local.properties`
（已 gitignore）写入：

```properties
TYRANOR_APPLICATION_ID=com.tyranor.next.test
```

产物包名为 `com.tyranor.next.test`，可与原版同时安装；`namespace` 仍为 `com.tyranor.next`，
`R` / `BuildConfig` 与源码包路径不受影响，Manifest 中的
`${applicationId}.fileprovider`、`${applicationId}.androidx-startup` 会随包名自动改写。

若希望**所有** debug 变体永久使用测试包名，应在 `app/build.gradle.kts` 的 `buildTypes` 中加
`debug { applicationIdSuffix = ".test" }`（本次未采用：发版流程与 CI 不在本方案改动范围内）。
