# 液态玻璃增强计划方案

> 目标：在应用设置新增下拉项「**导航栏样式**」，三选一 —— 默认 / **液态玻璃 · 经典** /
> **液态玻璃 · 透镜**（后者即本方案的高保真实现：三层采样 + 折射透镜 + 按压拖动，仅 Android 13+
> 提供，低版本归一化为经典档）。选择「默认」或「经典」时，既有实现**行为与画面完全不变**。
>
> 依据：《Tyranor-Next × Legado：液态玻璃底栏对比与高保真复刻方案》v1.1（下称「分析报告」）。
> 实现底座：Tyranor-Next `origin/main` @ `e9436f0`（分支已 rebase 到该提交）（分析报告核查基线为 `0f49e38`，
> 其后官方陆续合入圆角常量统一、玻璃顶栏修复与重构、Ren'Py 模块设置；本方案已在最新底座上完成 rebase）。

---

## 1. 决策记录

| 决策点 | 结论 |
|---|---|
| 新选项位置 | 与普通档合并为**同一个下拉 item**「导航栏样式」：默认 / 液态玻璃 · 经典 / 液态玻璃 · 透镜 三选一 |
| 显隐规则 | **Android 13 以下的设备不提供「液态玻璃 · 透镜」选项**（列表里不出现）；即使从新版备份恢复数据，读取时也会归一化为普通档 |
| 默认值 | 关闭。默认画面与改造前完全一致 |
| 生效条件 | `nav_style == liquid_glass_enhanced`（任意外观风格；低于 Android 13 时归一化为 `liquid_glass`） |
| 复刻路线 | 报告路线 **B**：沿用项目现有 Backdrop **1.0.2**（已含 `lens` / `CombinedBackdrop` / `InnerShadow`），按参考实现的光学参数与交互设计**独立实现**（见 §3.1 版权说明） |
| 轮廓 | 胶囊（`RoundedCornerShape(50%)`）替代 capsule 库的 `ContinuousCapsule`（见 §6 差异 D1） |
| 四项适配 | 保留 Tyranor 四项业务；手机按参考单槽宽度 76dp 居中收窄，平板/横屏（≥600dp）拉伸铺满，与原版液态玻璃导航一致（见 §6 D18） |
| 取消语义 | **取消不提交**，回到当前选中项（报告 §8.1「正式产品建议」，与源实现不同，见 §6 差异 D3） |
| 宿主转场 | **仅透镜档**在转场期间接受新目标（重定向）；默认路径保留原 `isRunning` 守卫（报告 §8.7） |
| 震动 | **新增触觉反馈**（源实现无此调用；用户要求，见 §6 D16），用 `performHapticFeedback`，无马达不触发 |
| 彩虹色散 | 不新增（源实现未启用 `chromaticAberration`，报告 §6.2） |

## 2. 开关模型

### 2.1 `core/settings/AppSettingsStore.kt`

| 项 | 内容 |
|---|---|
| key | `nav_style`（String，独立 `app_settings` prefs），三态取值 |
| 取值 | `default`（Material3 导航栏）/ `liquid_glass`（液态玻璃）/ `liquid_glass_enhanced`（液态玻璃 · 透镜） |
| 内存态 | `navStyleState: MutableStateFlow<String>`（默认 `default`） |
| 读取 | `getNavStyle(c)`；`initNavStyle(c)` 首次组合时加载（幂等） |
| 写入 | `setNavStyle(c, style)`（内部先归一化再落盘并广播） |
| 归一化 | `normalizeNavStyle(stored, enhancedSupported)`：未知值→`default`；透镜档在 Android 13 以下→`liquid_glass`（纯函数，有单测） |
| 迁移 | 早期实现把透镜档存成独立布尔 `liquid_glass_enhance`；`initNavStyle` 一次性升级为 `liquid_glass_enhanced` 并删除旧键 |

单项三态取代了「父开关 + 子开关」：不存在「父项已关、子项仍为 true」的隐藏态，
也就不需要任何复位语义；旧数据由迁移函数兜住。

**说明文案只保留「安卓版本提醒」**：下拉下方的摘要不再描述界面形态，只在需要的档位提示版本要求
（经典档 Android 12+、透镜档 Android 13+）；默认档不加摘要，保持界面简洁。

### 2.2 设置页 `ui/settings/AppSettingsActivity.kt`

```kotlin
OverlayDropdownPreference(               // 非布尔选择，按 AGENT.md 用下拉而非开关
    title = stringResource(R.string.settings_nav_bar_title),   // 底部导航栏
    summary = <当前档位的说明>,
    items = listOf(默认, 液态玻璃 · 经典, [液态玻璃 · 透镜]),            // 增强项仅在 Android 13+ 出现
    selectedIndex = navStyleIndex,
    onSelectedIndexChange = { AppSettingsStore.setNavStyle(ctx, style) },
)
```

**版权与实现方式（重要）**：本项目为 **GPL-2.0-only**，而参考项目
`HapeLee/legado-with-MD3`（其 `FloatingBottomBar.kt` 又自述衍生自 `weishu/KernelSU`）为 **GPL-3.0**，
两者不兼容。因此本方案**不复制上游代码表达**：算法、参数取值、渲染分层顺序属于不受版权保护的
设计要素，代码本身由本项目独立编写，**7 个实现文件全部为独立实现**，不保留 GPL-3.0 衍生署名：
- 手势识别器用单层状态机重写（上游是三段回调链）；
- 运动控制器**重新架构**为「一个帧循环 + 五个自写弹簧积分器」，不使用 `Animatable` /
  `MutatorMutex` / `snapshotFlow` / `VelocityTracker`，松手吸附与收材质是循环内的普通条件；
- 按压光斑的 AGSL 着色器为自写表达式（上游同位置为逐字节相同的移植版）；
- 栏体组件拆分为多个私有 Composable，构图与注释结构均与上游不同。

参考来源记于致谢：`legado-with-MD3` @ `fb01a76ebbbca41423e2c4c00080cc0861239fbd`。

## 4. 渲染链与参数

### 4.1 三层采样（报告 §6.1）

```text
页面内容 ─────────────────────────────→ pageBackdrop（MainScreen 录制）
    │
    ├─ A 可见栏：vibrancy → blur(8dp) → lens(24dp,24dp) → 表面色 40% → 边缘高光（无投影）→ 清晰图标
    │
    ├─ B 隐藏副本：clearAndSetSemantics + alpha(0f) + layerBackdrop(tabsBackdrop)
    │        内部：图标按 1→1.2 放大 + 强调色 tint
    │              └────────────────────→ tabsBackdrop
    │
    └─ C 移动透镜：CombinedBackdrop(page, tabs)
                   lens(10dp×p, 14dp×p, depth=true) + 内阴影 + 静止/按压覆盖 + 速度形变
```

Modifier 顺序按报告 §8.4 固定，不可调换（顺序错误会导致空采样、重影或裁切）。

### 4.3 交互（报告 §6.5 / §8.6）

- 按住透镜**立即**进入按压（`awaitFirstDown` 后即 press），无长按计时：材质与触觉反馈即时响应。
- **位置拖动要越过平台 touch slop**（`ViewConfiguration.scaledTouchSlop`）才开始；纯点击（含滑动途中
  轻点）不提交选中项，滑动目标与透镜位置都不受影响（见 §6 D24）。
- 拖动按 `dx / tabWidth` 累加目标索引，LTR/RTL 方向翻转，索引夹取在 `[0, N−1]`。
- 跟随位置使用源 spring，速度取**动画位置的采样速度**（非手指 px/s）。
- 松手：`round(target)` **吸附到整数槽位** → 提交切页 → 材质回落（位置先靠近目标再收）。
- 取消：**不提交**，透镜回到当前选中项。
- 点击：点击已覆盖图标立即给短震动；点击未覆盖图标则等滑块滑进 `tapArriveThreshold` 再给
  （连续点不同图标时只保留最后一次的等待，避免滑块「只是路过」就误触发）。
- 松手：一律**立即**给短震动（与材质回落同时），不做延迟。
- 快速重抓：控制器带会话编号，上一轮未完成的释放不会把新按下的透镜缩回去。

> 触觉反馈用 `View.performHapticFeedback`，不需要 `VIBRATE` 权限。参考实现没有震动，
> 这一条是本项目按用户要求新增（D16）。

## 5. 降级策略（报告 §8.8）

| 平台 | 行为 |
|---|---|
| API 33+ | 完整：实时模糊 + `lens` 折射 + `depthEffect` + 交互高光 shader |
| API 31–32 | 仅实时模糊 + 栏体透镜**不生效**（Backdrop 1.0.2 的 `lens` 在 < API 33 直接早退，栏体 lens 与透镜折射都是 no-op）；`Highlight` / `Shadow` / `InnerShadow` 由调用方在能力不足时传 `null`（不走无谓的离屏层）；`onDrawSurface` 仍绘制，因此选中态用主题色半透明胶囊兜底。与报告 §8.8「模糊 + 非折射选中反馈」一致 |
| API 26–30 | 无模糊：不透明实底 + 主题色半透明选中胶囊 |

能力由 `GlassBottomBarCapabilities.current` 单独表达，用户开关只决定「是否启用」，不参与能力判定。

**注意（评审后修正）**：设置里「液态玻璃 · 透镜」只在 **Android 13+** 出现，且读取时会归一化，
所以在本应用里上表的 31–32 / 26–30 两档**实际不可达**——它们只是组件层的能力分支（组件契约要求
能力可降级，便于将来复用到更低门槛的场景）。因此 V13「低版本降级分支」无法在应用内验证，
也不得在 PR 里宣称已覆盖。

## 6. 与源实现的显式差异（报告要求逐项记录）

| 编号 | 差异 | 原因 |
|---|---|---|
| D1 | 轮廓用 `theme/AppShapes.kt` 的 `AppNavCapsuleShape`（`RoundedCornerShape(50%)`）而非 capsule 库 `ContinuousCapsule` | 避免为新轮廓引入依赖：Backdrop 1.0.2 的 `lens` 只接受 `CornerBasedShape`，`ContinuousCapsule` 属 2.0.1 一档（其 lens 另有一条 `RoundedRectangularShape` 分支）。两者是不同几何类，本方案**不主张**像素等价，只主张胶囊几何下差异收敛（未实测） |
| D2 | 主题适配器放在 `ui/common/glass/` 而非报告建议的 `theme/` | 项目 `theme/` 当前不依赖 `ui/`，保持 `ui → theme` 依赖方向（AGENT.md 三层架构纪律） |
| D3 | 取消不提交（源实现 Cancel 与 End 调同一回调，可能提交） | 报告 §8.1「正式产品建议取消不提交」。**代价**：源实现取消时（无模糊档）仍会绘制中性 10% 覆盖，本实现改为回原项 + 主题色胶囊 |
| D4 | 速度归一化跨度与释放阈值固定为五项参考值（4 / 0.10） | 报告 §8.5「四项适配参数」，用于保持参考手感；**不得**表述为源码未改 |
| D5 | 用「**松手才收材质**」的状态标记取代挂起的释放流程 | 报告 §8.6 第 5 条要求正式版本处理「旧释放抢回新透镜」。本实现里 `beginPress()` 直接清掉 `shrinkWhenSettled`，不再存在旧协程把新按压缩回去的窗口（原方案用会话编号做到这一点，现已不需要） |
| D6 | 首次组合不播放「按下再回弹」过渡 | 源实现的 `LaunchedEffect` 在启动时会触发一次按压动画；Tyranor 启动画面不保留该脉冲 |
| D7 | 无折射能力时用主题色胶囊做选中兜底（源实现该档仍画中性 10% 覆盖） | 10% 中性覆盖在深色/复杂背景上不足以表达选中态，低版本需要可读的选中反馈 |
| D8 | 栏体宽度按窗口宽度夹取 | 报告 §9 窄屏风险：76dp 单槽在极窄屏可能放不下 |
| D9 | 拖动释放后不再重复播放一次按压脉冲 | 源实现 `onDragStopped` 已 `animateToValue(target)`，宿主回传 `selectedIndex` 时其 `LaunchedEffect` 会再触发一次；本实现按 `targetValue` 判重跳过第二次（影响 V02/V06 的像素阶段） |
| D10 | 依赖停留在 Backdrop **1.0.2**（源为 2.0.1）且不引入 capsule 库 | 报告 §7.2 路线 B。已核对：`Highlight` / `Shadow` / `InnerShadow` 数据默认值两版一致，折射 shader 字符串未变（唯一差异 `half4(1.0)` → `color`，白色默认下等价），残余像素风险集中在轮廓几何（见 D1） |
| D11 | ~~栏体不画外部投影（`shadow = null`）~~ **已被 D26 部分取代**：栏体改为与经典档相同的阴影；参考实现那套更强的投影仍不采用 | 源实现投影为浅色 10% / 深色 20% 黑、24dp 模糊、向下偏移 4dp，是本项目原液态玻璃栏（`Shadow.Default.copy(alpha = 0.8f)`，等效 8%）的 2.5 倍；在深色渐变背景上会形成一圈比栏体更大的暗色圆角轮廓（观感上像底栏下面还压着一层）。用户确认去掉。**注意**：移动透镜按压时（`pressProgress > 0`）的阴影与内阴影保留，静止时为 0，不产生常驻暗层 |

| D13 | 采样副本行的折射强度**随按压增长**（与参考实现一致） | 保真度优先：透镜里的图标会随按压一起被顶起来。代价是该离屏图层的采样边距随按压变化，按压期间每帧改变尺寸（重分配渲染目标）——属已知成本，已在 §7 列为待实测的性能项 |
| D15 | **浅色档可读性适配**：表面不透明度 0.40 → **0.62**、边缘高光 0.18 → **0.42**，并补一条 0.5dp 中性黑发丝描边（alpha 0.10） | 浅色页面底色本身很浅，40% 白叠上去与背景几乎同色——只有底栏后面有内容时才看得见轮廓（用户实测反馈）。按报告 §8.10「增强可读性」策略提高覆盖强度并补描边；深色档完全不变，表面仍为 0.40、无描边。三个数值都在 `GlassBottomBarSpec` 里单点可调 |
| D23 | **构造边界同样兜底**：`indexRange` 非有限/逆序退回 `0f..0f`，`initialIndex` 非有限退回范围起点、越界夹进范围 | 补审发现：逆序范围会让 `coerceIn` 抛异常；非有限初值会污染 `lastIndex` → `rawSpeed` 变 NaN → 速度弹簧永不收敛。归一化在构造期完成，运行期代码不必再防御 |
| D26 | **透镜档栏体阴影与经典档完全一致**（`Shadow.Default.copy(alpha = 0.8f)`，等效约 8% 黑） | 维护者实测反馈：透镜档此前是 `shadow = null`（D11），与经典档观感不一致、悬浮感更弱。两档现在用同一组阴影参数；参考实现那套「浅色 10% / 深色 20% 黑、24dp 模糊、下移 4dp」（2.5 倍强度、深色渐变上会压出更大的暗色轮廓）仍不采用。采样副本行保持 `shadow = null`（它不可见，只供透镜取样，加阴影会把暗边带进透镜内部） |
| D26b | **纯点击松手必须仍收回按压材质**（`releasePress()`） | 回归修复：D24 把「提交」与「收回材质」都绑在 `commitIndex` 上，导致纯点击不提交 = 也不收材质，滑块永久停在按下放大的状态（用户实测）。现在两者分离：`releasePress()` 只收材质、不动位置目标；提交仍只在真拖动时发生。新增回归用例 `releasePress_withoutDrag_collapsesButKeepsGlidingTarget` |
| D25 | **经典档浅色档补悬浮描边**：`Modifier.glassEdgeStroke(shape)` = 0.5dp 中性黑 10% 发丝线，沿栏体 16dp 圆角绘制 | 维护者实测反馈：纯白/浅灰页面上半透明表面与背景几乎同色，只有内容透到栏后时才看得见边界，悬浮感丢失。深色档不加（深底本身有对比 + 栏体自带高光/投影）；数值与透镜档浅色描边（`edgeStrokeWidth` / `edgeStrokeAlpha`）保持一致，避免两档观感漂移 |
| D24 | **拖动要越过平台 touch slop 才算数**，且**纯点击不提交** | 补审发现：识别器按设计对任何位移都上报，于是「滑动途中轻点一下」会被手指抖动判成拖动——透镜被截停、松手后提交到它当时路过的槽位（越过 slop 时 Tab 的点击已被取消，错误槽位就成了唯一结果）。改为：识别器累计位移超过 `ViewConfiguration.scaledTouchSlop` 才开始上报（并把累计位移一并交出），`onRelease(dragged)` 只在真的拖动过时才提交。**注意「不提交」不等于「不松手」**：纯点击走 `releasePress()`——立即收回按压材质、且不改动位置目标（既不把滑动中的透镜截停，也不会让滑块停在按下状态）。slop 是平台标准值，按压反馈仍是即时的（只有位置拖动等 slop） |
| D22 | **拖动起手把目标基准对齐到视觉位置** | 补审发现：动画途中抓住透镜再拖动时，位移会累加在上一轮的目标上（0→3 途中在 1.5 处抓住左拖一格会提交到 2，而非跟手的 0.5→1）。改为第一次拖动位移时 `targetIndex = index`，纯点击不受影响 |
| D21 | **运动参数在控制器初始化时统一兜底**：`visibilityThreshold` / `releaseThreshold` / `pulseVisibleThreshold` / `velocityNormalizationSpan` / `pressedScale` 非有限值回退默认、有限值夹取到合法区间；并强制 `releaseThreshold ≥ epsilon` | 这些值直接决定「是否已收敛」或充当除数。评审指出：阈值为 NaN/±Inf/>1 时判定永不成立，`pulsePending`/`shrinkWhenSettled` 清不掉，`allSettled()` 恒 false → 帧循环不再退出。另外补测试时又发现：收起阈值即使合法为 0 也会因严格小于永不成立，故必须 ≥ 弹簧自身的 settled 阈值 |
| D20 | **按压脉冲要先「看得见」再收材质**：`settleAt(pulse = true)` 记一个待播脉冲，等压力涨过 `pulseVisibleThreshold` 才允许收缩 | 评审发现：目标索引本来就在位时（例如刚拖动到位又点了一次），收缩条件会在第一帧把压力目标改回 0，这次按压等于没发生。改为脉冲可见后再收，近目标场景也有了按压反馈 |
| D19 | **宽屏下透镜宽度按参考单槽宽 76dp 封顶**：手势热区仍是整槽，视觉透镜居中且不超过 `spec.lensMaxWidth` | 平板/横屏拉伸后单槽可达 200dp 以上，透镜若等于整槽，按压时会膨胀成一块巨大胶囊（用户实测违和感强烈）。原版「经典」档的焦点胶囊固定 76dp，这里以参考单槽宽封顶 |
| D18 | **平板/横屏拉伸**：屏幕宽度 ≥ 600dp 时底栏拉伸铺满（与原版液态玻璃导航一致）；手机仍按参考单槽宽 76dp 居中收窄。命名同步调整为「导航栏样式」下的「默认 / 液态玻璃 · 经典 / 液态玻璃 · 透镜」 | 用户在平板上实测：居中短栏与玻璃风格下的全宽导航条观感不一致。窄屏仍保留参考比例（报告 §8.5） |
| D16 | **新增触觉反馈**（参考实现没有）：点击图标与松手各给一次短震动 | 用户明确要求「让操作更有反馈、更跟手」。用 `View.performHapticFeedback`（点击 `VIRTUAL_KEY`、松手 `CONTEXT_CLICK`），**不需要 VIBRATE 权限**，系统关闭「触感反馈」时自动静默。时机：点击未覆盖图标等滑块滑进 `tapArriveThreshold` 再震，点击已覆盖图标立即震；**松手一律立即震**（不做延迟，否则按下已选项会显得迟钝）；设备没有马达时不触发 |
| D14 | 按压光斑由**透镜的按压进度驱动**，不再单独维护跟手位置动画与更慢的一条弹簧 | 原方案的位置动画在其装配方式下并未参与绘制（每帧多一次协程却无视觉产出）；共用同一弹簧后亮度与体积同步，节奏更一致 |

此外，报告 §8.7 的宿主修复已实施：透镜档下 `MainScreen.selectPage()` 不再因转场 `isRunning` 丢弃输入，

### 9.1 测试用包名（调试包不与原版同包名）

调试包必须与原版 `com.tyranor.next` 不同包名，否则无法与原版共存安装。
本项目已有现成开关 `TYRANOR_APPLICATION_ID`（`app/build.gradle.kts:92`，读取顺序 env →
`local.properties` → Gradle property），因此**不改动入库的构建脚本**，只在本机 `local.properties`
（已 gitignore）写入：

```properties
TYRANOR_APPLICATION_ID=com.tyranor.next.test
```

产物包名为 `com.tyranor.next.test`，可与原版同时安装；`namespace` 仍为 `com.tyranor.next`，
`R` / `BuildConfig` 与源码包路径不受影响，Manifest 中的
`${applicationId}.fileprovider`、`${applicationId}.androidx-startup` 会随包名自动改写。

若希望**所有** debug 变体永久使用测试包名，应在 `app/build.gradle.kts` 的 `buildTypes` 中加
`debug { applicationIdSuffix = ".test" }`（本次未采用：发版流程与 CI 不在本方案改动范围内）。
