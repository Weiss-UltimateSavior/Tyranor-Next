# TyranorNext App 内三语言文本切换支持计划方案

## 1. 目标

为 TyranorNext 增加 App 内功能文本三语言切换：

- 简体中文 `zh`
- 日文 `ja`
- 英文 `en`

目标范围是“应用层功能文本”，也就是用户在 App UI、弹窗、Toast、通知、错误提示、设置项、按钮、菜单里能看到的文字。

不把引擎脚本、游戏内容、外置模块协议字段、URL、文件名、SharedPreferences key、Intent extra、JSON 协议字段纳入翻译。

## 2. 当前现状

### 2.1 资源文件现状

当前 Android 字符串资源只有：

```text
app/src/main/res/values/strings.xml
```

内容仅包含：

```xml
<string name="app_name">Tyranor Next</string>
```

也就是说，当前绝大部分功能文本都写在 Kotlin 源码里，尚未资源化/抽象化。

### 2.3 高优先级硬编码文本类型

优先迁移以下文本，因为它们用户可见、出现频率高、且会影响 App 内语言切换体验：

| 类型 | 例子 | 位置 |
| --- | --- | --- |
| 页面标题 | `首页`、`引擎`、`游戏目录`、`应用设置` | `ui/home`、`ui/engine`、`ui/settings` |
| 设置项 | `外观模式`、`色调切换`、`独立存档目录`、`游戏修改器` | `SettingsScreen.kt`、`AppSettingsActivity.kt` |
| 按钮 | `确定`、`取消`、`删除`、`保存`、`去下载` | 多个 UI 文件 |
| 弹窗标题/正文 | `删除游戏`、`发现新版本`、`启动失败` | `GameScreen.kt`、`SettingsScreen.kt` |
| Toast | `已保存`、`批量刮削正在进行`、`引擎设置已保存` | 多个 Activity/Screen |
| 通知 | `发现新版本`、`点击查看发布详情并下载` | `UpdateNotificationManager.kt` |
| 错误提示 | `无法解析游戏目录`、`补丁下载失败`、`授权失败` | `core/*` |
| 选项标签 | `自动`、`浅色`、`深色`、`关闭`、`启动时询问` | 设置映射表 |

## 3. 不应翻译或谨慎翻译的内容

这些字符串虽然被扫描到，但不应直接纳入语言切换：

| 类型 | 例子 | 处理方式 |
| --- | --- | --- |
| 协议字段 | `game`、`settings`、`orientation`、`rootUri` | 不翻译 |
| Intent action/package | `cyou.joiplay.runtime.renpy.run` | 不翻译 |
| 文件名/路径特征 | `script_version.txt`、`[游戏目录]` | `[游戏目录]` 可改成内部常量；文件名不翻译 |
| JSON 内容 | `{"useRuby18":true}` | 不翻译 |
| 品牌/服务名 | `VNDB`、`Steam`、`Bangumi`、`Hikarinagi` | 保留原名，只翻译描述 |
| 引擎名 | `Kirikiri`、`ONScripter`、`Ren'Py`、`RPG Maker` | 保留原名，只翻译解释文本 |
| 日志 Tag | `EngineScanner`、`RuntimeManager` | 不翻译 |

## 4. 推荐技术方案

当前项目是 `ComponentActivity + Compose`，没有实际引入 AppCompat Activity。为了减少迁移成本，推荐采用“资源文件 + Compose 本地化上下文”的混合方案。

### 4.1 资源目录

新增/完善：

```text
app/src/main/res/values/strings.xml       # 默认：简体中文
app/src/main/res/values-ja/strings.xml    # 日文
app/src/main/res/values-en/strings.xml    # 英文
```

也就是说，TyranorNext 的默认语言保持中文；用户不主动切换、系统语言未命中或资源回退时，都显示中文。

```text
values/strings.xml     # 简体中文，默认回退
values-ja/strings.xml  # 日文
values-en/strings.xml  # 英文
```

如后续需要更细地区分，可再增加 `values-zh-rCN`，但当前阶段不必复杂化。

### 4.2 App 内语言设置

新增应用语言配置：

```kotlin
object AppSettingsStore {
    const val LANGUAGE_SYSTEM = "system"
    const val LANGUAGE_ZH = "zh"
    const val LANGUAGE_JA = "ja"
    const val LANGUAGE_EN = "en"
}
```

设置页新增 item：

```text
应用设置 -> 语言
选项：跟随系统 / 简体中文 / 日本語 / English
```

### 4.3 运行时切换

新增 `AppLocaleController`：

- 读取 App 语言设置。
- 创建指定 Locale 的 `ConfigurationContext`。
- 提供 `rememberLocalizedResources()` 给 Compose。
- 语言切换后触发 Activity recreate 或刷新根 Composable 的 locale state。

推荐入口：

```kotlin
CompositionLocalProvider(
    LocalAppLocale provides appLocale,
    LocalAppStrings provides AppStrings(localizedContext.resources)
) {
    TyranorNextTheme { ... }
}
```

UI 层优先使用：

```kotlin
val strings = LocalAppStrings.current
Text(strings.settingsTitle)
```

或者直接资源化：

```kotlin
Text(stringResource(R.string.settings_title))
```

为了 Compose 页面重组自然，UI 页面文本推荐 `stringResource`；非 Composable 的 core/service/notification 层推荐通过 `context.getString(...)` 获取。

### 4.4 后台/通知/服务文本

后台更新通知、授权错误、补丁错误、存档错误不在 Composable 内，需要：

```kotlin
val localizedContext = AppLocaleController.wrap(context)
localizedContext.getString(R.string.update_notification_text)
```

否则 App 内切换语言后，通知栏仍可能跟随系统语言，而不是 App 设置语言。

## 5. 文本 Key 命名规范

推荐按功能域分组：

```text
common_confirm
common_cancel
common_delete
common_save
common_loading

nav_home
nav_games
nav_engine
nav_settings

```

规则：

- 公共按钮/状态统一 `common_*`。
- 页面/领域使用 `game_*`、`settings_*`、`engine_*` 等前缀。
- 带参数文本用 Android 格式化占位：

```xml
<string name="cover_scrape_result">Updated %1$d, skipped %2$d, failed %3$d</string>
```

Kotlin 使用：

```kotlin
context.getString(R.string.cover_scrape_result, updated, skipped, failed)
```

## 6. 迁移分阶段计划

### 阶段一：基础语言框架

1. 新增语言设置项。
2. 新增 `AppLocaleController`。
3. 增加/完善 `values/strings.xml`、`values-ja/strings.xml`、`values-en/strings.xml`。
4. MainActivity 根 Composable 接入 locale state。
5. 验证切换语言后无需重启或只需 recreate 即可刷新 UI。

验收标准：

- 应用设置页可以切换语言。
- 主页面 Tab、设置页标题、通用按钮能随语言切换。
- 重新进入 App 后保留用户语言选择。

### 阶段二：UI 层文本资源化

迁移优先级：

1. `ui/main/MainScreen.kt`
2. `ui/home/HomeScreen.kt`
3. `ui/game/GameScreen.kt`
4. `ui/engine/EngineScreen.kt`
5. `ui/settings/AppSettingsActivity.kt`
6. `ui/settings/SettingsScreen.kt`
7. `ui/settings/PerGameSettingsScreen.kt`
8. `ui/cover/CoverScraperSettingsActivity.kt`
9. `ui/save/SaveManagementActivity.kt`
10. `ui/patch/KrkrOnlinePatchActivity.kt`

验收标准：

- 主要页面无中文硬编码 UI 文本。
- 弹窗、Toast、按钮、菜单均可随语言切换。

### 阶段三：core 层用户可见文本资源化

迁移：

1. `core/game/launch/EngineLauncher.kt`
2. `core/game/save/GameSaveManager.kt`
3. `core/cover/*`
4. `core/patch/*`
5. `core/auth/*`
6. `core/updater/*`
7. `core/engine/external/*`
8. `core/engine/plugin/*`

处理方式：

- core 层不要直接依赖 Compose。
- 需要返回错误消息时，优先返回错误码/枚举，由 UI 层映射文本。
- 暂时难改的地方可先传入 localized context，使用 `getString`。

长期推荐：

```kotlin
sealed class LaunchError {
    data object MissingAllFilesAccess : LaunchError()
    data object CannotResolveGamePath : LaunchError()
    data class ExternalModuleMissing(val moduleName: String) : LaunchError()
}
```

UI 层统一：

```kotlin
LaunchError.toLocalizedMessage(context)
```

### 阶段四：扫描器/模型占位文本清理

当前扫描器里有：

```text
未命名游戏
未命名目录
[游戏目录]
```

建议：

- `未命名游戏`、`未命名目录` 改为资源化显示名，持久化时可存空或稳定 fallback key。
- `[游戏目录]` 不适合作为本地化文本长期保存在数据模型中，应改成内部常量：

```kotlin
const val LAUNCH_TARGET_GAME_DIR = "DIR"
```

展示时再本地化为：

- 中文：游戏目录
- 日文：ゲームフォルダ
- 英文：Game directory

### 阶段五：测试与防回归

新增测试/检查：

1. `strings.xml` 三语言 key 完整性检查。
2. Kotlin 硬编码中文扫描测试或 Gradle task。
3. 通知栏语言测试。
4. 设置切换语言后 Activity recreate/Compose 重组测试。
5. 格式化字符串参数数量一致性检查。

推荐加一个脚本或 Gradle task：

```text
checkHardcodedUiStrings
```

用于扫描：

```regex
"[^"]*[\u4e00-\u9fff\u3040-\u30ff][^"]*"
```

允许白名单：

- 文件名/协议字段
- 测试样例
- README/docs
- 日志 Tag

## 7. 翻译风格建议

### 7.1 中文

保持当前风格：简洁、直接、偏工具型。

示例：

```text
批量刮削封面
无法解析游戏目录
独立存档目录
```

### 7.2 日文

建议使用自然 App UI 语气，避免生硬机翻。

示例：

```text
批量刮削封面 -> カバー画像を一括取得
无法解析游戏目录 -> ゲームフォルダを解析できません
独立存档目录 -> 個別セーブフォルダ
```

### 7.3 英文

短按钮用常见 App 术语，错误提示保留原因。

示例：

```text
批量刮削封面 -> Fetch covers
无法解析游戏目录 -> Unable to resolve game directory
独立存档目录 -> Isolated save directory
```

## 8. 推荐实施顺序

建议不要一次性 433 处全改完，否则容易引入资源 key 错配和 UI 回归。推荐“小口吃鲸鱼”：

1. 先建立语言框架和公共字符串。
2. 迁主导航、设置入口、应用设置页。
3. 迁游戏页和弹窗。
4. 迁引擎设置/单游戏设置。
5. 迁 core 层错误和通知。
6. 加硬编码扫描防回归。

每阶段都跑：

```bash
./gradlew :app:testDebugUnitTest assembleDebug --no-daemon
```

## 9. 当前结论

当前项目具备接入三语言切换的条件，但必须先做文本抽取。最大工作量集中在：

```text
SettingsScreen.kt
GameScreen.kt
PerGameSettingsScreen.kt
GameSaveManager.kt
```

建议优先建立资源化框架，再逐文件迁移。这样既能快速让入口页面支持中/日/英切换，也能避免一次性大改造成大量 UI 文案错漏。

## 10. 实施记录

已按本方案完成首轮落地：

1. 新增 `AppLocaleController`，为 Compose 页面、通知、Toast、core/service 层统一提供 App 内语言上下文。
2. `AppSettingsStore` 新增语言配置，默认值为简体中文 `zh`。
3. 应用设置页新增“语言”设置项，可切换：
   - 简体中文
   - 日本語
   - English
   - 跟随系统
4. 新增并补齐三套资源：
   - `app/src/main/res/values/strings.xml`
   - `app/src/main/res/values-ja/strings.xml`
   - `app/src/main/res/values-en/strings.xml`
5. 主页面、首页、游戏页、引擎页、设置页、应用设置页、封面设置页、存档管理页、在线补丁页、单游戏设置页、引擎设置页均已接入资源文本。
6. 启动错误、封面抓取错误、Hikarinagi 授权错误、VNDB/Steam/Bangumi 搜索错误、在线补丁错误、更新通知文本、存档管理错误已接入 App 内语言。
7. 扫描器默认名称和启动目标占位已改为资源/稳定常量。
8. 新增 `tools/check-hardcoded-ui-strings.py`，并注册 Gradle 任务 `:app:checkHardcodedUiStrings`，用于：
   - 检查三语言 `strings.xml` key 是否一致；
   - 阻止 Kotlin 中新增可见中/日文字符串字面量。

当前验证结果：

```bash
python3 tools/check-hardcoded-ui-strings.py
./gradlew :app:checkHardcodedUiStrings --no-daemon
./gradlew :app:compileDebugKotlin --no-daemon
./gradlew :app:assembleDebug --no-daemon
```

以上均已通过。
