## 两项 P2

|编号|问题原因|修复方式|影响与边界|
|---|---|---|---|
|P2-1|官方 Artemis 的自动版本尚未解析游戏候选，设置预览却当作固定受支持版本；实际首选可能不支持|设置页对自动选择显示“滤镜支持取决于实际内核”，保留用户请求；启动与兼容回退仍按实际候选核验，不放宽库门禁|仅区分设置期条件支持与运行期能力。不能保证自动选出的每个内核都支持；不支持的实际候选仍保留原画面|
|P2-2|纯 Lanczos 双轴水平目标无条件要求 RGBA16F，缺半浮点可渲染能力时整链永久失败|仅纯缩放的水平中间目标改为 RGBA8，预算同步按四字节估算；CNN 的中间目标保持 RGBA16F|解除纯缩放对半浮点目标的要求；接受 RGBA8 的量化及负波瓣裁剪。CNN 本身的能力要求不变，不宣称修复不支持 CNN 的 GPU|

## P3 逐项响应

编号沿用原审查报告。

|编号|处理结论|依据、修复及剩余边界|
|---|---|---|
|3|保留整对象拒绝策略|损坏配置或未知滤镜链按完整快照回退，不逐字段拼接旧状态与新状态；读取不主动重写磁盘。避免局部保留改变既有继承、空链及迁移 marker 语义；不是已修复损坏数据的承诺|
|4|已修复|Siglus 在 producer 尚未交付 Rust 的准备阶段增加 10 秒主线程看门狗。超时先关闭候选，阻止迟到交付，再按当前直出窗口世代恢复步进；清理继续由原 GL owner 排队执行，不跨线程解绑或销毁|
|5|未确认，保留边界|attach 失败不等同于解绑完成。没有真实驱动证据证明 BAD_SURFACE/BAD_NATIVE_WINDOW 时可安全忽略 unbind 失败；不能因此提前把屏幕交回 Rust。暂不放宽解绑成功判据|
|6|不增加笼统 Error 捕获|默认 Android 未捕获异常会终止进程，尚未证明所述“进程继续而仅 worker 席位泄漏”路径；捕获所有 Error 后继续 EGL 清理可能破坏所有权。原有 RuntimeException 有界清理与席位限制保留，不宣称覆盖所有 VM/驱动致命错误|
|7|文档已修正|仅在状态回报类和方法可用后才能上报安装失败；取得入口之前的类加载等早退只记录日志。移除文档对全部早退均可显示故障的过度描述|
|8|已修复|完成的 FAILED 先通过 JNI 轮询交付至少一次，之后才允许新建解绑请求；待完成与成功请求不被替换。恢复失败仍可到达官方 DeviceReset 路径|
|9|确认语义差异，延期|当前重建上下文会清除着色器失败锁存，与旧进程级策略不同。需要区分编译失败与目标/上下文失败；本轮不以保留全部 mFailed 或全局静态缓存代替设计，以免阻断合法恢复。后续专项处理|
|10|已修复本层分配出口|同步字符串传参改用 UTF 作用域引用，避免 std::string 二次分配；JNI 已有异常原样保留返回。新增引擎所有权表登记捕获 bad_alloc，先销毁未发布 Rust 实例再释放窗口；既有登记原地替换，不在 Rust 接管后分配表项。未把 Rust 内部 panic/驱动故障包成成功|
|11|已修复|KR 的单游戏版本与内核先走同源白名单合并；无效覆盖跟随合法全局，全局无效回到 auto。设置预览与实际启动使用相同解析，移动存储限制保留|
|12|保留内部不变量检查|编码入口的 require 用于已校验的内部链约束，读取、菜单、节点数和参数确认均有门禁；未确认合法用户点击可触发此异常。没有新增英文 UI 错误通道，也不为不可达不变量堆叠异常包装|
|13|已清理|移除两个无引用的 ART 旧读取 getter；只读迁移仍使用的键、模式常量和 normalizer 保留|
|14|现有校验保留，增强延期|普通 Android CI 校验提交资源与 manifest 的 SHA，可检出单独修改库或资源；不等同于从外部上游重建。CAS 生成器复现检查与 native workflow 的触发范围增强后续单独处理，不把同提交清单当独立来源证明|
|15|已修复|基础 Anime4K 独立携带完整 MIT 文本及来源、Git blob、SHA 记录，并指定字节保留属性；移除可选 extra 贡献不会移除基础许可登记。不新增算法或许可证类型|

## 保留的限制

除了表内延期项，真实 GPU 故障、永久驱动挂起、厂商线程迁移、全部打包库二进制布局、共享软渲染引擎与 API 26/27 键盘仍无新增设备覆盖。后台分析器位置、原版 KR2 亦有的纯色偏色、文本排除仍延期。自研 Artemis 画质增强接入待上游合并；CuNNy2、自定义导入、调试工具与附件不进入候选。

提交者此前确认官方 Artemis 开启超分游玩约两小时正常，该验收对应此前版本，不代替本轮新增故障分支验证。提交者没有进行人工代码审查；独立 Agent 静态复核不能标成人工代码审查。
