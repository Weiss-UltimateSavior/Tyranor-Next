## 资源保留的安全取舍

官方 Artemis 通常在宿主退出时终结对应进程；不能把 Siglus 跨次累积的相同前提不加区别地套用。两者仍共享同一准入实现，避免并发创建或待释放 owner 绕过上限。

本次不采用“集合满后移除最老句柄”或“新 worker 成功 makeCurrent 后强制销毁旧 context”。旧 worker 解绑失败时没有安全的所有权转交证明，驱逐 Java 引用不能证明 native EGL 资源已释放，跨 owner 回收可能引入窗口竞争。保留失败 owner 及其席位，减少新功能可用性以保护原呈现和游戏实例。没有新增定时 GL 清理线程、自动杀进程或重跑游戏。

该修复界定持有数量而非驱动显存总字节；一个失败驱动调用仍可能卡住其 owner。真实驱动故障的恢复和窗口时序没有本轮设备验证，不声称永久故障可被完全回收。
