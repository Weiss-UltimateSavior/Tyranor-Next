## 一、总览

| 层级 | 机制 | 典型内容 | 主要代码位置 |
|---|---|---|---|
| ① | Room / SQLite | 游戏库、扫描根、快捷启动、单游戏覆盖、引擎检测缓存 | `core/game/storage/` |
| ② | SharedPreferences XML | 应用设置、引擎设置、prefs 回滚镜像、OAuth/WebDAV 凭据、更新通知状态 | `app/src/main/java/com/tyranor/next/core/` |
| ③ | 内部文件存储 | 引擎插件、封面、字体、存档镜像、WebDAV 本地版本/检查点、SAF 索引 | `core/cover/`、`core/game/launch/`、`core/game/save/sync/`、引擎模块 |
| ④ | 外部专属存储 | 各引擎 scoped 存档、在线补丁临时下载、截屏回退目录 | `EngineLauncher.kt`、`GameSaveManager.kt`、`ScreenCapture.kt` |
| ⑤ | 游戏目录内写入 | 引擎默认存档、patch.tjs、引擎偏好 XML | 引擎模块、`ArtemisPfsUnpacker.kt` |
| ⑥ | 硬编码 /sdcard 路径 | JoiPlay RTP（含导入现场文件）、截屏（DCIM/tyranornext）、RPG Maker configuration.json | `RpgMakerExternalEngineModule.kt`、`RpgMakerRuntimeEnvironment.kt`、`ScreenCapture.kt` |
| ⑦ | 系统托管存储 | WorkManager 内部任务 DB、WebView localStorage/IndexedDB | `BackgroundUpdateWorker.kt`、`SaveSyncWorker.kt`、`TyranoActivity.kt` |

数据流特点：

- **游戏库主数据**存在 Room 数据库 `databases/game_library.db`；`game_scanner.xml` 仅保留为旧版回滚镜像和首次迁移来源（`GameLibraryRepository.kt`）。单游戏覆盖以 DB 的 `game_overrides` 表为 App 侧事实源，`tyranor_game_overrides.xml` 作为引擎子进程可读镜像。
- **游戏库数据库不进入备份**：`game_library.db`、`game_library.db-wal`、`game_library.db-shm` 均被排除；恢复后由 prefs 镜像和启动修复重建。`noBackupFilesDir/save_sync/` 与 WorkManager 自身的 `no_backup/androidx.work.workdb*` 也不参与备份或设备迁移。
- **App 进程与引擎子进程**（`:kirikiri2`、`:krkrsdl3`、`:tyrano`、`:artemis*`、`:ons`）通过共享 prefs 文件（`tyranor_prefs`、`tyranor_game_overrides`、`onsyuri`）交换设置，全部为 `MODE_PRIVATE`，无 `MODE_WORLD_*` / `MODE_MULTI_PROCESS`。
- **存档位置**由「scoped save 开关」决定：开启时写入应用专属目录（内部或外部），关闭时直接写入游戏目录；每游戏可覆盖全局默认。

## 二、Room/SQLite 与 SharedPreferences

### 2.1 应用数据库

物理位置：`/data/data/com.tyranor.next/databases/game_library.db`

| 数据库 | 定义位置 | 表 / 内容 | 备份策略 |
|---|---|---|---|
| `game_library.db`（当前 schema v2） | `core/game/storage/GameLibraryDatabase.kt` | `games`（游戏库主表、最近打开时间）、`scan_roots`、`quick_launch`、`game_overrides`（每游戏覆盖）、`engine_detection_cache`（可重学缓存） | DB、`-wal`、`-shm` 全部排除出云备份与设备迁移。`game_scanner.xml` / `tyranor_game_overrides.xml` 镜像用于迁移与恢复重建 |

Room schema 导出到 `app/schemas/`。v1→v2 与降级重建是有限的历史兼容策略；后续 schema 变更必须提供显式 `Migration`。旧 `game_scanner.xml` 在 DB 写入后仍会防抖回写，供旧版本回滚读取；它不是当前版本的游戏库事实源。

WorkManager 使用独立的内部 SQLite 数据库，见第七节。

## 七、系统托管存储

### 7.1 WorkManager 内部数据库

- WorkManager 使用自身内部 SQLite（androidx-work-runtime-ktx 2.11.2），数据库位于 `noBackupFilesDir/androidx.work.workdb`（含 `-journal` / `-wal` / `-shm`），任务**跨重启保留**但不参与云备份或设备迁移。
- 更新检查链：`background_update_check`，OneTime、`NetworkType.CONNECTED`、`ExistingWorkPolicy.KEEP`（`BackgroundUpdateWorker.kt`）。
- WebDAV 保存同步固定使用四条当前唯一工作链（`SaveSyncWorker.kt`）：

| Unique work name | 触发形态 | Pull | 初始延迟 | 策略 |
|---|---|---:|---:|---|
| `webdav_save_open_now` | 前台/启动后立即同步 | 是 | 1 秒 | `APPEND_OR_REPLACE` |
| `webdav_save_exit_now` | 游戏退出、恢复版本或已登记待上传 | 否 | 1 秒 | `APPEND_OR_REPLACE` |
| `webdav_save_open_fallback` | 打开链 busy/可重试失败后的后台兜底 | 是 | 30 秒 | `KEEP` |
| `webdav_save_exit_fallback` | 退出链 busy/可重试失败后的后台兜底 | 否 | 30 秒 | `KEEP` |

- 四条 WebDAV 链均要求 `NetworkType.UNMETERED`，使用 `LINEAR` 15 秒 backoff；fallback 链在 `runAttemptCount >= 5` 时失败并保留已持久化 sessions，等待下次前台或手动调度。
- 关闭 WebDAV 时除取消上述四条链外，也会取消历史名称 `webdav_save_open`、`webdav_save_exit`、`webdav_save_fallback`。
- 关闭 WebDAV 时在同一次 `webdav_sync_secure` prefs 提交中写入 `enabled=false` 与递增的 `disable_generation`，并同步快照 session key/token/activeKey。session 保存启动时的 `enabledGeneration`；旧 ticket 在异步 sweep 取得锁前即因 generation 不匹配被拒绝，进程重启后也保持失效。新 launch 只继承 generation 与当前值相同的 pending baseline；启动前忙碌判定同样过滤旧 generation 的 ticket 与启动宽限，但独立宿主进程探测仍保留；较旧快照不删除较新宽限，失败启动仅移除自身 generation/token 的宽限。异步 sweep 在 `active -> session` 锁内只删除与快照 token 相同的记录，不检查清理时的总开关；`whileEnabled` 同时复核持久 generation 与 enabled。每次顶层及嵌套 DAV exchange 发出前都重新执行事务准入并复核持久 generation、session/current 条件及已固定的 revision/activeKey；检查与请求入队在同一短临界区内完成，网络响应等待不持有本地版本或目录锁。
- 配置保存或重置只推进 `config_revision`，不推进 `disable_generation`：既有 session、ticket 与启动宽限保留。`SaveSyncService` 在本地事务入口比较配置快照 revision，`WebDavClient` 还在真实 HTTP 请求入队前经同一准入检查复核；旧配置的在途事务不能继续提交后续请求，下一轮使用新配置重试。关闭总开关的 generation 失效语义与配置修改相互独立。
- 云端裁剪检查点在 `noBackupFilesDir/save_sync/checkpoints` 持久化 `needsPrune`、`publicationIntent` 与 `publicationConfirmed`。每个游戏每个同步轮次中，所有经 `SaveSyncService` 发起的远程 DELETE 合计最多 20 次；超限后报告 `cleanupPending`，不删除待上传 session，自动 fallback 会继续。下一轮先重新确认有效的新对象，再从持久检查点继续裁剪，因此相同存档字节和已有 S→N 链不会被提前清掉。Service 已确认的 `needsPrune` 会在 capture/pin 前 fresh verify；active 为空或 pin 创建失败仍可续清，但验证所需空间和 checkpoint 可持久化必须成功，验证失败不删旧版本；Runtime 以 pending cleanup 优先于非空 hash 差异判断，20 次预算保留 marker，新 M 可同轮发布，create/copy ENOSPC 统一为不重试的 `STORAGE_FULL`。
- `directory_selections/` 由实际目录 `activeKey` 的 SHA-256 文件名索引；导入前写入 `ownerUri` / `ownerToken` / `revision`，首次 begin 另存 `previousRevision`。owner 保留到 journal 清理成功；删除 journal 前先持久化 `completionCommitted`，journal 已删而 owner 残留时按该结果完成释放。`resume` 只允许续接同一 token 的当前 epoch 或没有 revision 的 legacy 空 epoch，另一 alias 已推进后不得回退 revision。所有 alias 在恢复与按 `activeKey` 扫描的 session/baseline 清理完成前 fail closed；committed completion 只清 owner/token 并保留新 revision 以判定旧 alias pinned transfer 已过期，已证明的 precommit abort 则恢复 `previousRevision`。所有历史新增、维护与恢复淘汰都保护 pending `selected`、`beforeHash` 及 `promotionAwaitingChange`/legacy-or-stale `promotionNeedsRecovery` 所需的有效 `promotionFromHash` source。未消费 promotion 同时绑定 `promotionActiveKey` 与 `promotionDirectoryRevision`，另一 URI 推进同一目录 revision 后旧 promotion 暂停。completed promotion 的目录或 revision 缺失、为空、与当前目录不匹配都会触发“处理未完成切换”：恢复保留 active N、有效历史 S 与恢复材料，清除未知 promotion ancestry，不导入存档；该路径适用于所有已接入统一存档管理的引擎，MV/MZ 互通仍受独立开关与格式边界约束。之后按普通 N 同步，当前同版本显式重选仅为可选重建链路径。
- 应用清单移除了 `WorkManagerInitializer`，改为 `Configuration.Provider` 懒初始化（`TyranorNextApplication.kt`、`AndroidManifest.xml`）。

## 八、备份与数据迁移策略

`app/src/main/AndroidManifest.xml`：

```xml
android:allowBackup="true"
android:dataExtractionRules="@xml/data_extraction_rules"   <!-- API 31+ -->
android:fullBackupContent="@xml/backup_rules"              <!-- API <31 -->
```

两个规则文件（`app/src/main/res/xml/backup_rules.xml`、`data_extraction_rules.xml`）**排除以下凭据与游戏库数据库文件**：

```xml
<!-- OAuth：新文件使用 Keystore 密钥，换机不可解密；旧文件仅迁移期存在 -->
<exclude domain="sharedpref" path="hikarinagi_auth_secure.xml" />
<exclude domain="sharedpref" path="hikarinagi_auth.xml" />
<!-- WebDAV 配置使用 AndroidKeyStore 密钥 -->
<exclude domain="sharedpref" path="webdav_sync_secure.xml" />
<!-- Room 主 DB 与 WAL/SHM 整体排除，恢复后由 prefs 镜像重建 -->
<exclude domain="database" path="game_library.db" />
<exclude domain="database" path="game_library.db-wal" />
<exclude domain="database" path="game_library.db-shm" />
```

`data_extraction_rules.xml` 在 `cloud-backup` 与 `device-transfer` 两个场景均应用同一组排除项。排除 DB 的原因不是可重建数据不重要，而是云端快照可能出现主文件与 WAL 不一致；恢复后由 `game_scanner.xml`（games/roots/quick launch/最近游玩）和 `tyranor_game_overrides.xml`（单游戏覆盖）经启动修复重新导入。`engine_detection_cache` 属于可重学缓存，不保证随备份恢复。

**含义**：除凭据、Room 数据库与 `noBackupFilesDir` 数据外，其余数据——`game_scanner.xml` 回滚镜像、`tyranor_game_overrides.xml` 镜像、所有引擎设置（`tyranor_prefs` 等）、封面、字体、scoped 存档（内部 `krkr_mirror` 与外部 `save/`）、WebView localStorage——会进入云备份与设备迁移。

例外：`noBackupFilesDir/androidx.work.workdb*`、整个 `noBackupFilesDir/save_sync/` 树与 `noBackupFilesDir/krkr_saf_index/*.idx` 因位于 `noBackupFilesDir` 天然不参与备份或设备迁移。`save_sync/` 包含 WebDAV 版本 ZIP、检查点、激活恢复、session/baseline、宿主记录和手动选版标记，详见第三节。

移除游戏清理该 URI 的版本、激活记录/ZIP、检查点（含旧身份/服务器的已登记键）、session、baseline 和同步身份，不删除云端版本；目录 owner 在 journal 及其余子项清理成功前保持占用，子项失败保留 URI 主状态中的身份及 `checkpointKeys` 归属索引，全部子项成功后才清除主状态；失败恢复游戏库条目供重试。宿主登记为进程级，不随单游戏删除。导入交换另在存档目录旁保存 `.import_transaction`，staging 内的 `.tyranor_import_commit` 随目录提交移动；无提交证据的旧备份保留为 `.import_orphan_<UUID>`。上述相邻恢复材料不属于 WebDAV 历史裁剪对象。


> 注意：SAF URI 持久化权限（`scan_roots` 中的 tree URI）在恢复备份后可能失效，需用户重新授权。

## 九、敏感数据与风险点

审计数据静态安全时的高信号项：

1. **Hikarinagi OAuth 令牌**：当前令牌写入 `hikarinagi_auth_secure.xml`，字段为 AndroidKeyStore AES/GCM 加密的 Base64 密文；密钥不随 prefs 保存。旧 `hikarinagi_auth.xml` 可能短暂保留明文以等待迁移重试。新旧文件都排除云备份与设备迁移，避免换机后出现不可解密数据或带出旧明文。
2. **默认云备份仍包含游戏与设置数据**（见第八节）：`game_scanner.xml`、`tyranor_game_overrides.xml`、引擎设置、封面、字体、scoped 存档和 WebView 存储可进入备份；`hikarinagi_auth*`、`webdav_sync_secure.xml` 与 `game_library.db*` 不进入。若需更严格的隐私边界，可继续缩小允许范围或改为 `allowBackup="false"`。
3. **WebView DOM Storage 开启**：第三方 Tyrano/RPG Maker 网页游戏代码可写入持久化 localStorage；配合 `usesCleartextTraffic="true"`（`tyrano_external_network` 开启时加载外部资源），需注意供应链面。
4. **`krkr_bridge.cpp` 的任意路径写 JNI**：`NativeBridge_write` 不限制目标路径，依赖 Kotlin 调用方自律。
5. **`game_scanner.xml` 兼容格式**：该文件已退居 Room 回滚镜像，但字段仍以 `\u0001` 分隔，游戏名含特殊字符时依赖编解码正确性，属于自定义格式的健壮性风险（非安全风险）。
6. **外部 `save/` 目录随应用卸载删除**（`Android/data` 语义），用户存档如未导出会丢失；`GameSaveManager` 提供导出 zip 功能兜底。
