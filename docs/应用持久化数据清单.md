## 一、总览

| 层级 | 机制 | 典型内容 | 主要代码位置 |
|---|---|---|---|
| ① | SharedPreferences XML | 应用设置、引擎设置、游戏库记录、OAuth 令牌、单游戏覆盖 | `app/src/main/java/com/tyranor/next/core/` |
| ② | 内部文件存储 | 引擎插件、封面、字体、存档镜像、补丁覆盖、SAF 索引 | `core/cover/`、`core/game/launch/`、引擎模块 |
| ③ | 外部专属存储 | 各引擎 scoped 存档、在线补丁临时下载 | `EngineLauncher.kt`、`GameSaveManager.kt` |
| ④ | 游戏目录内写入 | 引擎默认存档、patch.tjs、引擎偏好 XML | 引擎模块、`ArtemisPfsUnpacker.kt` |
| ⑤ | 硬编码 /sdcard 路径 | JoiPlay RTP 音源、RPG Maker configuration.json | `RpgMakerExternalEngineModule.kt` |
| ⑥ | 系统托管存储 | WorkManager 后台任务 DB、WebView localStorage/IndexedDB | `BackgroundUpdateWorker.kt`、`TyranoActivity.kt` |

数据流特点：

- **游戏库主数据**存在 `game_scanner.xml`（Prefs 内 `\u0001` 分隔的行式记录），而非数据库；进程内有 `gamesCache` 等内存缓存加速主页重组（`EngineScanner.kt:47-53`）。
- **App 进程与引擎子进程**（`:kirikiri2`、`:krkrsdl3`、`:tyrano`、`:artemis*`、`:ons`）通过共享 prefs 文件（`yukihub_prefs`、`tyranor_game_overrides`、`onsyuri`）交换设置，全部为 `MODE_PRIVATE`，无 `MODE_WORLD_*` / `MODE_MULTI_PROCESS`。
- **存档位置**由「scoped save 开关」决定：开启时写入应用专属目录（内部或外部），关闭时直接写入游戏目录；每游戏可覆盖全局默认。

## 七、系统托管存储

### 7.1 WorkManager 内部数据库

- 任务名 `background_update_check`，OneTime + 网络约束 + `ExistingWorkPolicy.KEEP`（`BackgroundUpdateWorker.kt:48-57`）。
- WorkManager 使用自身内部 SQLite（androidx-work-runtime-ktx 2.11.2 标准行为），任务**跨重启保留**。
- 应用清单移除了 `WorkManagerInitializer`，改为 `Configuration.Provider` 懒初始化（`TyranorNextApplication.kt:12-13`、`AndroidManifest.xml:31-40`）。

### 7.2 WebView 存储（:tyrano 进程）

- `TyranoActivity.kt:377-390` 开启 `domStorageEnabled = true`、`databaseEnabled = true` → Chromium 的 **localStorage / IndexedDB / WebSQL** 持久化在 WebView profile 目录。
- 游戏存档**不依赖** WebView 存储：经 JS 桥（`TyranoStorage`，`TyranoStorage.kt:9-111`）写 `.sav`（UTF-8 文本/base64）到存档目录；RPG MV/MZ 经 `__hook_rmmz_managers.js` 写 `.bin`。
- 无 CookieManager / WebViewDatabase 直接调用；应用全局 `usesCleartextTraffic="true"`。

## 八、备份与数据迁移策略

`app/src/main/AndroidManifest.xml`：

```xml
android:allowBackup="true"                          <!-- 行 18 -->
android:dataExtractionRules="@xml/data_extraction_rules"   <!-- 行 19（API 31+） -->
android:fullBackupContent="@xml/backup_rules"       <!-- 行 21（API <31） -->
```

两个规则文件（`app/src/main/res/xml/backup_rules.xml`、`data_extraction_rules.xml`）**仅排除一个文件**：

```xml
<exclude domain="sharedpref" path="hikarinagi_auth.xml" />
```

（`data_extraction_rules` 在 `cloud-backup` 与 `device-transfer` 两个场景均排除该文件。）

**含义**：除 `hikarinagi_auth.xml` 外，其余全部数据——游戏库记录（`game_scanner.xml`）、所有引擎设置（`yukihub_prefs` 等）、每游戏覆盖、封面、字体、scoped 存档（内部 `krkr_mirror` 与外部 `save/`）、WebView localStorage——都会进入云备份与设备迁移。

例外：`noBackupFilesDir/krkr_saf_index/*.idx` 因位于 `noBackupFilesDir` 天然不参与备份。

> 注意：SAF URI 持久化权限（`scan_roots` 中的 tree URI）在恢复备份后可能失效，需用户重新授权。

## 九、敏感数据与风险点

审计数据静态安全时的高信号项：

1. **`hikarinagi_auth.xml` 明文令牌**：access/refresh token 以明文存于 SharedPreferences（`HikarinagiAuthStore.kt:48-56`）。项目无 `security-crypto` / EncryptedSharedPreferences 依赖；唯一缓解是备份排除规则。
2. **默认全量云备份**（见第八节）：如需收紧，应在 `data_extraction_rules` 中补充排除 `game_scanner.xml`、`hikarinagi_auth` 之外的令牌类数据，或改为 `allowBackup="false"`。
3. **WebView DOM Storage 开启**：第三方 Tyrano/RPG Maker 网页游戏代码可写入持久化 localStorage；配合 `usesCleartextTraffic="true"`（`tyrano_external_network` 开启时加载外部资源），需注意供应链面。
4. **`krkr_bridge.cpp` 的任意路径写 JNI**：`NativeBridge_write` 不限制目标路径，依赖 Kotlin 调用方自律。
5. **`game_scanner.xml` 行式格式**：字段以 `\u0001` 分隔，游戏名含特殊字符依赖转义正确性，属于自定义格式的健壮性风险（非安全风险）。
6. **外部 `save/` 目录随应用卸载删除**（`Android/data` 语义），用户存档如未导出会丢失；`GameSaveManager` 提供导出 zip 功能兜底。
