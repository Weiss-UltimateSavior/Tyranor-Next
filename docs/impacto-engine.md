# impacto 引擎接入与验收

本接入复用 CommitteeOfZero 的 impacto 运行时，不重新实现 MAGES. 虚拟机。上游固定版本为 `ba0b6e0884b9016fcd7dfd3e50024c5af1e8aef7`；实现计划见 [impacto-engine-integration-plan.md](impacto-engine-integration-plan.md)。

> 当前是实验接入。引擎构建、合成夹具和启动协议测试不等于商业游戏兼容性验收；上游也没有声明任何游戏已经完整实现。真实设备与游戏验收结果须单独记录，当前结果见 [验收记录](impacto-acceptance.md)。

## 游戏准备与识别

仅使用自己合法取得、与上游对应平台版本匹配的游戏资源；本仓库不提供原版游戏数据、解密材料或商业存档模板。

在游戏实际资源目录根部创建 UTF-8 文件 `impacto.json`，例如：

```json
{"version":1,"profile":"chlcc"}
```

- 文件最多 4096 字节，只允许 `version` 和 `profile` 两个字段；版本必须是整数 `1`。
- 不允许重复字段、额外字段、尾随内容、无效 UTF-8、大小写不匹配的 profile 或任意路径、脚本和启动参数。
- 游戏目录直接存放该 profile 所需资源，不必再加一层同名 profile 子目录。例如 `chlcc` 的 `BG.CPK`、`SCRIPT.CPK` 等与描述文件位于同一级。
- 当前允许的八个 profile 为 `chlcc`、`chlcc-switch`、`cclcc`、`cclcc-switch`、`mo6tw`、`darling`、`dash`、`rne`。名称与必须存在的文件/目录以 [固定 profile 元数据](../engine/impacto/profiles.json) 为准；上游标为隐藏或未完成的 profile 仍然不代表可通关。
- `.cls` 列表对应的同名资源目录必须保留；结构化脚本目录的大小写、层级和文件名必须与所选版本一致。
- `.cpk`、`.mpk` 或类似文件名不是可靠的游戏身份，不据此猜测 profile；同一组文件名可能属于不同作品或版本。
- 重新扫描目录后入库。已有引擎的强特征优先级保持不变，描述文件不会覆盖已经识别的其他引擎。

SAF 可以读取描述文件并识别目录，但原生运行时只能读取可映射为真实路径的本地资源。仅提供 `content://` 流的云端/特殊文档提供方不能直接运行；不会暗中复制整个游戏或把 URI 当文件路径。

## 运行条件和能力边界

- 本运行时使用 Android 9（API 28）及以上、ARM64、OpenGL ES 3.2。TYN 全局的 Android 8 最低版本保持不变，设备不满足条件时只拒绝启动 impacto。
- 设备报告 GLES 3.2 不保证实际 EGL 创建一定成功；原生错误仍可能导致独立引擎进程退出。
- 触摸、键盘、手柄及游戏菜单由上游 SDL/impacto 实现负责。没有据此宣称 TYN 自定义图形滤镜、虚拟键重映射、统一存档管理、WebDAV 存档同步或任意汉化补丁已经支持。
- profile 由每个游戏自己的描述文件决定；不使用全局 profile 覆盖所有游戏。TYN 宿主不支持上游补丁配置，原生设置页隐藏对应开关，并忽略旧 TOML 的补丁启用值而不抹掉其他用户设置。
- 未提供真实运行库或资源包的开发构建会显示运行库缺失，并在请求游戏存储权限前拒绝启动。没有占位 `.so` 或回退到其他引擎。

## 私有资源、配置与存档

`engine-runtime/impacto.zip.xz` 保存原生运行库；`impacto-runtime/` 保存独立的资源清单与压缩包。两者不同，不能用仅面向 `.so` 的 `NativeRuntimePack` 解压任意资源。

资源先在私有目录暂存，核对 SHA-256、大小、条目数与规范路径后原子发布为不可变版本。拒绝目录穿越、符号链接、重复条目、缺失文件和超限内容。旧的完整资源版本不在新版本安装失败时被替换，也不覆盖正在使用的资源。

每个游戏以原始库记录 URI 的 SHA-256 区分私有用户目录。游戏存档与持久 `user.toml` 不在可替换资源目录内；同一 profile 的两个安装目录不会共用存档。移动目录或重新以不同 URI 添加不会自动迁移旧存档。不要在原生会话仍运行时手工修改这些私有文件。

每次启动产生单独的可信 Lua 配置，只加载随包 profile；不执行游戏目录内自带 Lua。配置以完整 argv 元素传递，正确转义引号、控制字符和非 ASCII 路径。VFS 只重映射已审核的游戏资源路径，包括结构化挂载的 `Path` 和 `Order`，保留挂载顺序及过滤条件。已知的存档路径（包括 MO6TW 的硬编码路径）重定向到本游戏私有目录。

## Android 宿主与 SDL 隔离

`com.core.impacto.ImpactoActivity` 运行在非导出的独立 `:impacto` 进程中。上游存在 `exit()` 和全局状态，不能在 TYN 主进程内承载或假设 Activity 销毁已结束所有原生写入。退出时保留 SDL 的终止事件和会话锁，短暂等待后再给原生线程最多 10 秒后台宽限；若仍未结束，只强制终止该引擎进程，锁随进程死亡释放。强制退出可能使尚未写完的存档不完整，不能称为保证保存成功。

impacto 使用独立的 SDL 3.4.10 Java/JNI 命名空间 `org.libsdl.impacto`，静态链接在自己的运行库内。TYN 原有的 SDL2、SDL2x、krkrsdl3 的 SDL3 3.4.12 类和二进制不替换。宿主按绝对路径加载运行库，恢复最近任务时重新核对当前资源/原生包，不回退到任意文件系统脚本。

## 构建、来源与许可

- 构建入口：`tools/impacto/build-native.sh`；固定输入：`engine/impacto/source-lock.json`。
- 原生源码补丁保存在 `engine/impacto/patches/`。构建不依赖移动的 `master`，包括 LibAtrac9 在内的 FetchContent 输入固定到提交。
- 原生构建需要独立的现代 CMake、Android NDK 与 vcpkg；不提高 TYN 普通 JNI 桥的 CMake 要求。普通 Gradle 构建不隐式重建全部原生依赖。
- 运行资源保留上游声明的许可与来源；Noto 字体单独适用 OFL 1.1。部分字体图集/游戏图标的原始素材来源没有独立核实，不能描述成所有素材的权利链均已认证。
- 静态链接的 FFmpeg、libmspack、OpenAL Soft 等有额外义务，不能把整个 `.so` 标为仅 ISC。实际分发须同时提供正确许可、完整对应源码与可用构建/重链接材料，不能只有下载链接清单。

## 验收记录的要求

发布前分别记录：

1. 描述解析、文件/SAF 扫描与原引擎优先级的回归。
2. 路径转义、资源损坏/超限/中断、存档隔离、会话竞争、取消与任务恢复测试。
3. 原生 ELF 的 ARM64/API、JNI 名称与版本、动态依赖、`SDL_main` 和 16 KiB 对齐。
4. JVM、三语言检查、Android lint、Debug APK 和启用 R8 的 Release 构建/回调保留。
5. 真机的标题画面、文字、输入、音频、视频、存读档、后台恢复、退出后重开及主进程存活，并回归 ONS 与 krkrsdl3。

具体结果须区分「通过」「失败」「未运行」。没有真实设备和合法相符样本时，最后一项保留未验收，PR 保持草稿，不据编译结果扩大兼容性声明。
