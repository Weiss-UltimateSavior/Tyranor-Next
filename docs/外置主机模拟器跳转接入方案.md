# 外置主机模拟器跳转接入方案（PPSSPP / Eden）

> 来源：RinneMobile 的掌机模拟器跳转链路复盘（`com/core/launcher/HandheldLaunchers.kt`、`ExternalGameLaunchers.kt`、`EnginePackageResolver.kt`、`EngineDetector.kt`）。
> 目标：TyranorNext 支持把 PSP / Nintendo Switch 游戏跳转给外置模拟器运行，并在游戏扫描中识别、入库这两类游戏；同时引擎页新增一个「外置跳转支持」展示项，弹窗列出 PPSSPP 与 Eden。
> 范围：仅「跳转外置模拟器」。不内置 PSP/Switch 运行时，不接管存档（由外置模拟器管理）。RPG Maker / Ren'Py / Artemis 等既有外置 APK 模块体系不变。

> 实施状态：**已完成**（按 §11 推荐默认执行）。落地要点：
> - `EngineType.PSP` / `EngineType.NINTENDO_SWITCH` + `EmulatorTarget` / `ExternalEmulatorRegistry` / `ExternalEmulatorLauncher`；
> - ROM 身份采用「uri = ROM 文件 URI」（一 ROM 一条）；扫描在 SAF/File × 全量/增量 4 条路径逐条发射；
> - 启动在 `resolveGameDirectory` 之前分流到外置模拟器，未安装返回类型化失败（Snackbar 文案 + 引擎页下载引导）；
> - 引擎页新增「外置跳转支持」展示项，弹窗列 PPSSPP / Eden，未安装跳下载页、已安装打开模拟器主界面；
> - `<queries>` 加两包、`file_paths.xml` 扩 `external-path`/`root-path`，存档管理与单游戏设置对两类游戏显式标注“由模拟器管理”。
> 保留项：§11 的决策点为推荐默认，未收到反对即按此实施；如后续调整（如未安装改成弹窗直给下载按钮）再单独修改。

## 1. 背景

RinneMobile 已实现一整套外置模拟器跳转策略注册表，其中与本计划相关的是：

| 主机 | 包名 | Activity | Intent 契约 | 识别扩展名 |
| --- | --- | --- | --- | --- |
| PSP（PPSSPP） | `org.ppsspp.ppsspp` | `org.ppsspp.ppsspp.PpssppActivity` | `ACTION_VIEW` + `dataAndType(uri, "*/*")` + `setClassName` + `NEW_TASK\|GRANT_READ\|GRANT_WRITE` | `.pbp` `.cso` `.iso` `.chd` |
| Switch（Eden） | `dev.eden.eden_emulator` | `org.yuzu.yuzu_emu.activities.EmulationActivity`（yuzu 命名空间） | `ACTION_VIEW` + `dataAndType(uri, "application/octet-stream")` + `setClassName` + `NEW_TASK\|GRANT_READ` | `.nsp` `.xci` `.nca` `.nro` |

共同点：`getPackageInfo` 探测安装、未安装直接失败且**不回退通用包启动**、URI 走 SAF `content://`、显式组件启动。

TyranorNext 现状差异：

- 无 PSP / Switch 引擎类型，扫描只遍历目录且「一目录一游戏」，`ScanGame.uri` 是唯一身份（`GameEntity.@PrimaryKey val uri`）；
- 启动前必须 `resolveGameDirectory` 解析出目录，文件型目标会失败；
- 无模拟器包注册表、无相关 `<queries>`、`FileProvider` 只覆盖 `updates/`；
- 引擎页只渲染 `supportedEngines`，没有“非引擎展示项”的位置。

## 2. 关键设计决策

### 2.1 ROM 游戏身份：`uri = ROM 文件 URI`（默认方案，待确认）

一个 ROM 一条游戏，`ScanGame`：

```kotlin
ScanGame(
    title = <ROM 文件名去扩展名>,
    uri = <ROM 文件 URI>,        // SAF: content://...（buildDocumentUriUsingTree 产物）；File 回退: 绝对路径
    engine = EngineType.PSP | EngineType.NINTENDO_SWITCH,
    launchTarget = <ROM 文件名>,  // 仅作展示/编辑参考
)
```

理由与影响：

- **唯一性**：`uri` 是主键，一 ROM 一条天然唯一；`PerGameSettingsStore` / 最近 / 快捷 / 检测缓存键全部成立。
- **根归属**：`GameRootMatcher` 按 documentId 前缀匹配，`primary:Games/PSP/X.iso` 属于 `primary:Games`，天然成立。
- **启动**：外置跳转直接用 `game.uri`，无需解析目录。
- **必须绕行**：`EngineLauncher.launchInternalChecked` 的分流要放在 `resolveGameDirectory` **之前**（content:// 文件会返回 null）。
- **存档**：`GameSaveManager` 返回“不支持”，游戏抽屉隐藏存档管理。
- **封面**：目录内仅一个 ROM 时复用 `findLocalCoverUri`，多 ROM 时不设。

被否方案：`uri=目录 + #rom=...` 合成键（需在 N 个消费点剥离，改动面大）；`一目录一条取首个 ROM`（合集被折叠）。两者均不采用，除非核对时另行决定。

### 2.2 启动链绕行

PSP / Switch 不经过 `EnginePluginBootstrap`、不进入 `EngineLauncher.buildIntent`，在 `resolveGameDirectory` 之前分流到 `ExternalEmulatorLauncher`。

### 2.3 引擎页展示

PSP/Switch **不加入** `EngineLauncher.supportedEngines`（避免被当成“已集成引擎”打勾行）。改为在引擎列表后追加一个固定展示项「外置跳转支持」，弹窗列 PPSSPP / Eden 两条。

## 3. 新增抽象

```kotlin
// core/engine/external/EmulatorTarget.kt
data class EmulatorTarget(
    val engine: EngineType,            // PSP / NINTENDO_SWITCH
    @StringRes val displayNameRes: Int,
    val packageName: String,           // org.ppsspp.ppsspp / dev.eden.eden_emulator
    val activityName: String,          // 显式组件类名

    val targets: List<EmulatorTarget>
```

- `installUrl`：PPSSPP `https://www.ppsspp.org/`（或 Play 商店）；Eden `https://git.eden-emu.dev/eden-emu/eden/releases`。

## 4. 扫描识别与入库

### 4.1 扩展名（默认集合，待确认）

- PSP：`.pbp` `.cso` `.iso` `.chd`（暂不含歧义的 `.elf`）
- Switch：`.nsp` `.xci` `.nca` `.nro`

### 4.2 `EngineScanner` 改动点

文件：`core/game/scan/EngineScanner.kt`

- 新增 ROM 判定与发射函数，例如：
  ```kotlin
  private fun romEngineOf(name: String): EngineType?   // 扩展名 → PSP/SWITCH
  ```
- 在 4 条遍历/增量路径中，`detectEngine` 未命中后发射本层 ROM：
  - SAF 全量 `traverseDirectories`（198-235）
  - SAF 增量 `scanRootIncremental`（138-173）
  - File 回退全量 `traverseFileDirectories`（419-450）
  - File 回退增量 `scanRootIncrementalFile`（384-417）
- SAF 用 `SafNode.uri`（`buildDocumentUriUsingTree` 产物，自带 tree 授权）；File 用 `File.absolutePath`。
- 标题 = 文件名去扩展名；封面 = 目录内仅一个 ROM 时复用 `findLocalCoverUri`。
- 发射后是否继续下钻：默认**发射本层 ROM 且继续下钻子目录**（避免漏嵌套合集），最终按 `uri` 去重（`scanRootInternal` 已有 `seen` 去重）。
- 优先级：目录先按 `detectEngine` 判引擎；命中引擎则不发射 ROM（引擎优先）。

### 4.3 其余持久化/清理

- `GameRecordCodec` / `GameEntity` / `ScanGameIntents`：使用 `EngineType.name`，新增枚举自动兼容，无需改。
- 已删清理：确认对“文件型 `uri`”的存在性判定（目录存在性检查需兼容文件），必要时补 `DocumentFile`/`File.isFile` 分支。
- `EngineDetectionRepository.recordScanDetections`：`when(game.engine)` 的 `else -> null` 已兜底，ROM 类不写检测行。

## 5. 启动跳转

### 5.1 `ExternalEmulatorLauncher`

```kotlin
// core/engine/external/ExternalEmulatorLauncher.kt
object ExternalEmulatorLauncher {
    data class Result(val success: Boolean, val code: String, val target: EmulatorTarget)
    fun launch(context: Context, target: EmulatorTarget, game: ScanGame): Result
}
```

流程：

1. `isPackageInstalled` 探测；未安装返回 `package_not_installed`。
2. URI 归一：
   - `content://` → 直接使用；
   - `file://` 或绝对路径 → 经 `FileProvider`（`${applicationId}.fileprovider`）转为 content URI。
3. 构建 Intent：`ACTION_VIEW` + `setDataAndType(uri, target.mime)` + `setClassName(target.packageName, target.activityName)` + `FLAG_ACTIVITY_NEW_TASK | FLAG_GRANT_READ_URI_PERMISSION`（`grantWrite` 时加 `FLAG_GRANT_WRITE_URI_PERMISSION`）。
4. 捕获 `ActivityNotFoundException` / `SecurityException` / 其他异常 → 类型化 code。

### 5.2 `EngineLauncher` 接入

`launchInternalChecked` 在 `resolveGameDirectory` 之前：

```kotlin
ExternalEmulatorRegistry.forEngine(game.engine)?.let { target ->
    currentCoroutineContext().ensureActive()
    val result = ExternalEmulatorLauncher.launch(context, target, game)
    if (result.success) {
        GameLibraryFacade.recordRecentGame(context, game)
        return LaunchResult.Success
    }
    return LaunchResult.Failure.ExternalEmulatorFailed(result)
}
```

- `EngineLauncher.buildIntent` 的 `when(engine)` 增 PSP/SWITCH 分支：`error("handled by ExternalEmulatorLauncher")`。
- `EngineLauncher.supportedEngines` **不**新增 PSP/SWITCH。

### 5.3 结果与文案

- `LaunchResult.Failure` 增 `data class ExternalEmulatorFailed(val result: ExternalEmulatorLauncher.Result)`。
- `ui/common/LaunchErrorMessages.kt` 增映射：未安装 / 无匹配 Activity / 被拒 / 启动异常，均带目标名（PPSSPP / Eden）。
- 未安装的默认处理（待确认）：仅 Snackbar 文案提示 + 引导去引擎页「外置跳转支持」下载；可选增强为弹窗直给「去下载」按钮。

### 5.4 存档与抽屉

- `GameSaveManager` 的 `when(game.engine)` 增 PSP/SWITCH → `SaveLocation(null, no_file_interface, false)`。
- `GameScreen.shouldShowSaveManagement` 增排除 PSP/SWITCH（与 `ExternalEngineModuleRegistry.isExternalEngine` 并列）。
- `RpgSaveFormat` / `EffectiveEngineSettings` 的 `else` 分支已兜底，无需改。

## 10. 风险与注意事项

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| `uri` 语义变化 | ROM 游戏的 `uri` 是文件而非目录，影响所有假定“目录”的消费点 | 外置跳转在 `resolveGameDirectory` 前分流；存档/清理显式兼容文件 uri；测试覆盖 |
| content:// 与 file:// 混用 | File 回退路径传 `file://` 会 `FileUriExposedException` | 优先 SAF；File 回退走 FileProvider（扩展 file_paths） |
| 包可见性 | 未加 `<queries>` 时安装探测恒为未安装 | 阶段 0 加两个包；不引入 `QUERY_ALL_PACKAGES` |
| 扩展名误判 | `.iso/.chd` 等较通用 | 仅作 ROM 候选；引擎特征优先；后续可加内容魔数校验 |
| 扫描量增大 | ROM 合集目录会产生大量条目 | 复用现有 depth/去重；必要时后续加“只扫首层 ROM”开关 |
| 多 ROM 目录下钻 | 可能重复/过多条目 | 按 `uri` 去重；如需可改为“命中 ROM 层不再下钻” |
| 外置模拟器行为不受控 | 存档、金手指、DL 由模拟器管理 | 明确“不接管存档”，隐藏存档管理入口 |
