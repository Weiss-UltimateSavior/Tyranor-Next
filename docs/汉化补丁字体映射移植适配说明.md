# 汉化补丁字体映射移植适配说明

> 性质：**移植/适配说明**（非 App 功能设计）。说明如何把 jis 替换 / jis 隧道 / 映射字体型汉化补丁的**字符映射**适配到 TyranorNext（Android）上正常显示，供移植者与玩家参考。
> 边界与免责：TyranorNext **不内置、不自动加载**补丁的注入 DLL、映射表或字体，也不会在扫描/启动时读取它们；本文只描述**手工适配方法**。游戏数据、补丁及其映射/字体派生物的版权归原权利方所有，请自持合法副本，**不要分发**提取出的映射表或生成后的字体。
> 适用范围：以 FVP（rfvp）引擎的汉化补丁为主；其它引擎思路相通，但字体/编码模型不同，细节需另行适配。

---

## 1. 原理速览

### 1.1 四类补丁与模拟器表现

| 代号 | 补丁类型 | 文本存储方式 | Windows 侧还原方式 | 模拟器（TyranorNext/rfvp）表现 |
|---|---|---|---|---|
| T4 | **GBK 注入** | 文本直接以 GBK 写入脚本，并修改引擎码页 | 无（引擎按 GBK 读取） | 只要把**文本编码设为 GBK** 即可正常 |
| T1 | **jis 替换** | Shift-JIS，简中字被替换为**生僻日文汉字**占位 | 注入 DLL（UIF / GalTransl / 自制框架）按映射表还原 | 占位字被原样显示 → 混着正常字的「错乱」 |
| T2 | **jis 隧道** | Shift-JIS，简中字替换为 **SJIS 未定义码位** | 注入 DLL + `sjis_ext.bin`/`jis_ext.bin` 顺序表还原 | 缺字：rfvp 对无字形字符输出**空白** |
| T3 | **映射字体** | 同 T1（占位字） | 补丁字体自身 cmap 把占位字指向目标字形（GalFC/日繁字体） | 未把该字体当主字体时显示占位字；**直接用该字体即可** |

### 1.2 为什么模拟器会「错乱」

1. 还原逻辑在 **Windows 注入 DLL**（`winmm.dll`/`version.dll`/d3d9 代理/游戏私有 DLL）里，Android 无法执行；
2. 脚本里保存的本来就是**占位字**（生僻日文汉字或未定义码位），没有映射层时会被当作正常文字渲染；
3. rfvp 渲染缺字时输出空白（不是方框），所以 T2 表现为「掉字」；
4. T3 的映射在**字体文件**里，若引擎仍按原字体渲染占位字，同样错乱。

适配的核心只有一步：**让引擎用「占位字 → 目标字形」的映射来渲染**。Android 侧有两种等价手段：

- **重映射字体（推荐，本说明主流程）**：改写一枚字体的 cmap，使占位字的码位指向目标字的字形，再把该字体设为引擎主字体；
- （备选，需引擎支持）运行时字符替换：在文本解码后按映射表把占位字替换为目标字。

## 2. 第一步：判定补丁类型

### 2.1 文件信号速查

| 游戏目录中的文件 | 提示类型 | 说明 |
|---|---|---|
| `uif_config.json` 且含 `replace_chars` | T1（映射来源清晰） | `source_chars` → `target_chars` 明文给出 |
| `uif_config.json` 且含 `tunnel_decoder` | T2 | 配合 `mapping`/`sjis_ext.bin` |
| `sjis_ext.bin` / `jis_ext.bin` | T2 | 隧道扩展字符顺序表 |
| `jis_map.bin` | T1（Babel 类框架） | 映射外置文件 |
| 根目录 `*.dll` 且含 `VNTextProxy`/`UniversalInjectorFramework`/`babel`/`jis_map.bin` 等字符串 | T1/T2（映射可能**内嵌在 DLL**） | 例：《樱花，萌放。》的 `Sakura.dll` |
| 根目录或 `font/` 下的 `*.ttf/otf/ttc` | 可能是 T3（映射字体）或生成用的基础字体 | 见 §3.4/§4.2 |
| 无上述文件但文本含大量生僻汉字 | T1（来源需从脚本与 DLL 推断） | 见 §3.3 |

### 2.2 文本抽样确认

FVP 脚本（`.hcb`/`.bch`）中的字符串是 `0x0E <u8 长度> <字节…>`（pushstring）。抽样统计：

- 按 Shift-JIS 解码后，若**生僻汉字（JIS 第 2 水准/罕用字）占比明显偏高**，且常见简体字较少 → T1；
- 若出现 Shift-JIS **未定义序列**（解码失败/替换字符）→ T2；
- 若按 Shift-JIS 解码乱码但按 GBK 解码通顺 → T4（改编码即可）；
- 参考实现见附录 C 的抽样脚本（仅读取脚本、不修改任何文件）。

## 3. 第二步：获取「占位字 → 目标字」映射

按以下优先级尝试，拿到映射后统一导出为中间格式（附录 B：`fvp_map.tsv` / `fvp_map.json`）。

### 3.1 UIF 配置（最省事）

`uif_config.json` → `text_processor.rules[]` → `type: replace_chars`：

```
"source_chars":  "這説為凜…"      // 占位字（脚本中实际存储的字符）
"target_chars":  "变为动视显…"      // 目标字（应显示的中文）
```

两个字符串**逐位配对**（UTF-16 码位一一对应），直接导出 TSV 即可。

### 3.2 外置映射文件

- `jis_map.bin`（Babel 类框架）：为二进制映射容器。可用同目录的注入 DLL 作为参考实现（其解析代码在 DLL 中），或对同一补丁改用 §3.3 的内嵌提取；
- `sjis_ext.bin` / `jis_ext.bin`（隧道）：文件内容通常是**无法用 SJIS 表示的字符列表**；隧道码位按顺序分配。需要结合具体框架的分配规则（VNTextPatch / UIF 隧道），并用脚本抽样验证覆盖率后再使用。

### 3.3 注入 DLL 内嵌映射（重点：T1 常见）

不少补丁把映射表**编译进 DLL**（例：《樱花，萌放。》的 `Sakura.dll` 内嵌 1206 条 `(u16 占位字, u16 目标字)`）。

**手工定位（有反汇编工具时）**

1. 在 DLL 中搜索字符串 `jis_map.bin` / `jis_ext.bin` 的引用；
2. 找到加载分支附近的「读取表 + 循环次数」代码（如某地址被赋给指针、循环计数为常量 `0x4B6`）；
3. 表通常为 4 字节一条：`(u16 key, u16 value)`；**key 是占位字本身的 Unicode 码位**（少数实现用 SJIS 码位，脚本两种都扫描），value 为目标字的 Unicode。

**通用启发式提取（无符号信息也能用）**

1. 扫描 DLL 中连续的 `(u16,u16)` 序列：要求 key 大多能按 Shift-JIS 解码、value 大多落在 CJK 区；
2. 用**脚本里的实际占位字**做校验：计算「表 key 与脚本字种的交集」与「表内 key 在脚本中的出现比例（precision）」；
3. 取交集最大且 precision ≥ 0.5 的候选表；导出为 TSV。

参考脚本：附录 C `extract_map.py`（不写入 DLL，只读扫描）。

### 3.4 映射字体（T3）与标准映射表

- **T3**：补丁自带字体可能已内嵌映射。判据：用该字体渲染若干占位字，若字形与参考字体（系统 Noto/思源）同码位字形明显不同，则该字体就是映射载体 → **无需生成**，直接把该字体作为引擎主字体（§5.3）；
- **标准映射表**：GalTransl/SExtractor 的 `hanzi2kanji_table.txt`（简中 → 日文汉字）。仅当补丁确实用它生成时可用；与脚本占位字覆盖率不足则不要用。

### 3.5 映射校验（生成字体前必做）

| 检查 | 要求 |
|---|---|
| 覆盖率 | 映射 key 覆盖脚本抽样中的占位字 ≥ 95% |
| 唯一性 | 同一占位字只有一条映射 |
| 无链式 | 映射的值不再作为其它条目的 key（避免需要多次替换） |
| 目标有效性 | 全部目标字在基础字体 cmap 中存在（见 §4.4） |

不满足时不要生成，回到 §3 换来源或改用 T3/手动方案。

## 4. 第三步：生成重映射字体

### 4.1 原理

TrueType/OpenType 字体通过 `cmap` 表把「字符码位」映射到「字形」。重映射字体即：

```
cmap[占位字码位] = cmap[目标字码位]     // 复用目标字的字形
```

这样引擎按占位字渲染时，实际画出的就是目标中文字形；其它正常字符不受影响。

### 4.2 基础字体选择

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | **游戏自带 CJK 字体**（根目录或 `font/`） | 例：《樱花，萌放。》自带 `NotoSansCJKsc-Regular.otf`；风格与游戏一致 |
| 2 | 系统 CJK 字体（Android `/system/fonts`） | 设备差异大；TTC 需选简体 face；生成前做覆盖校验 |
| 3 | 自带/下载 Noto Sans CJK SC | 覆盖最稳；注意体积与授权（OFL） |

### 4.3 生成步骤（fontTools）

```bash
pip install fonttools
python3 build_remap_font.py 基础字体.otf fvp_map.tsv 输出字体.otf
```

脚本见附录 C `build_remap_font.py`；要点：

- 遍历 `cmap` 中所有 **Unicode 子表**（format 4/12），执行 `cmap[占位] = cmap[目标]`；
- **TTC**：先选定 face（fontTools 用 `TTFont(path, fontNumber=n)`），建议选含简体覆盖的 face；
- 不修改字形与度量，只改映射，字体大小基本不变；
- 生成失败（格式异常）不要使用半成品；输出到独立文件名。

### 4.4 自检与验证

1. **缺失目标检查**：脚本会统计「目标字不在基础字体 cmap」的条数，应为 0；不为 0 时换基础字体；
2. **样张渲染**：用生成字体渲染脚本中抽取的一句占位文本，确认显示为通顺中文；
3. **覆盖率抽查**：多抽几处文本（对话、菜单、人名）检查；
4. **游戏内验证**：见 §5.4。

## 5. 第四步：在 TyranorNext 中启用

### 5.1 传入设备

把生成的字体复制到手机任意可访问位置（如 `Download/`），与游戏放一起也可。

### 5.2 FVP「自定义字体（强制）」

TyranorNext → **引擎设置 → FVP → 自定义字体** → 选择生成的字体（或到**单游戏设置**里只对该游戏生效）：

- **角色**：该字体作为主字体强制生效，绕过脚本的字体请求与字体枚举；
- **文本编码**：T1/T2/T3 保持 **Shift-JIS**（默认值）；若误设为 GBK 反而会全篇错乱；
- **系统字体回退**：建议保持开启，作为缺字兜底；
- **改动需重新进入游戏生效**（字体在引擎创建时注入）。

### 5.3 按类型的最简路径

| 类型 | 需要做的事 |
|---|---|
| T4 | 仅把该游戏「文本编码」设为 **GBK**（无需字体） |
| T1/T2 | 按 §3 获取映射 → §4 生成字体 → 按 §5.2 选择字体 |
| T3 | 无需生成，直接把补丁自带字体按 §5.2 选择即可 |

### 5.4 验证与还原

- 验证：进入游戏对话/菜单，确认占位字变为中文且无掉字；
- 还原：把「自定义字体」改回**跟随游戏默认**即可恢复原样；生成的字体文件可自行删除。

## 6. 完整示例：《樱花，萌放。》（Babel / jis 替换）

### 6.1 实测数据

| 项 | 值 |
|---|---|
| 注入 DLL | `Sakura.dll`（x86，d3d9 代理）；含 `babel::sjis_cp932_to_unicode_engine`、`jis_map.bin` 等字符串 |
| 映射位置 | 不在游戏目录（无 `jis_map.bin`）→ 内嵌：文件偏移 `0x47960`（RVA `0x48960`），**1206 条 × 4 字节** `(u16,u16)`，循环计数 `0x4B6` |
| 映射样例 | `寅→她、諍→说、徼→这、禳→—、戍→你、弗→么…` |
| 脚本覆盖 | 64,994 条字符串中，1206/1206 条映射全部出现；无链式映射 |
| 交叉验证 | Windows 截图原句 `透慓窗疋贍微的梍隙，不知从何杣峨来了点点春色禳禳` → 映射 → `透过窗户细微的缝隙，不知从何处飘来了点点春色——`，逐字一致 |
| 基础字体 | 游戏自带 `NotoSansCJKsc-Regular.otf`（16.4MB） |
| 产物 | `SakuraMoyu_CN_remap.otf`（16.4MB，4 个 Unicode cmap 子表改写，目标缺失 0） |
| 结果 | FVP 自定义字体（强制）= 该字体、编码 SJIS → 真机实测显示正常 |

### 6.2 步骤

```bash
# 1) 抽样确认类型（T1）并提取内嵌映射
python3 extract_map.py Sakura.hcb Sakura.dll
#    → [unicode] 已导出 fvp_map.tsv：dll:0x47960，1206 条，脚本命中 1206，precision 100.0%

# 2) 生成重映射字体（用游戏自带字体）
python3 build_remap_font.py NotoSansCJKsc-Regular.otf fvp_map.tsv SakuraMoyu_CN_remap.otf
#    → cmap 子表 4 个, 缺失目标 0 条

# 3) 自检：渲染「寅痲燬嵋着倦意的小嘴，稾稾地……」，应显示：
#    「她张开带着倦意的小嘴，轻轻地……」
```

4) 把 `SakuraMoyu_CN_remap.otf` 传到手机 → TyranorNext FVP 自定义字体（强制）选择它 → 文本编码保持 Shift-JIS → 重进游戏。

## 7. 给补丁作者 / 移植者的建议

1. **希望补丁在模拟器上开箱可用**：随补丁附带一枚**重映射字体**（GalFC 思路），或附带映射表与说明，让用户自行生成；
2. **不要在 Android 侧加载 Windows DLL**：DLL 是 x86/Windows 二进制，无法在 Android 执行，且自动加载补丁资产存在版权与安全风险；
3. **映射数据与字体派生物不要公开再分发**：属于对补丁/游戏资产的再加工，建议只在本机使用，或由补丁作者在其补丁许可允许的范围内提供；
4. 若补丁使用 GBK 注入，请在补丁说明中明确告知「请把模拟器文本编码设为 GBK」，可避免大量误报。

## 8. FAQ

| 问题 | 回答 |
|---|---|
| 生成的字体很大吗？ | 与基础字体基本同尺寸（只改 cmap，不动字形）。用游戏自带字体时通常 10–30MB |
| 可以多款游戏共用一个生成字体吗？ | 映射与基础字体都相同时可以；不同补丁的映射不同，需各生成一份 |
| 生成后个别字仍是生僻字？ | 说明该占位字不在映射表中（提取不完整）；补充映射后重新生成 |
| 个别字空白/掉字？ | 基础字体缺该目标字形，换覆盖更全的基础字体（如 Noto Sans CJK SC） |
| TTC 字体只生效首个 face？ | 生成时显式选 face；游戏内直接使用时也可能只取首 face，建议选出后另存为独立 TTF/OTF |
| 游戏内字体菜单还能用吗？ | 强制字体优先级最高，游戏内选择会被覆盖；如需用游戏内菜单，改用「跟随游戏默认」并手动把生成字体放进游戏 `font/`（是否被选用取决于脚本） |
| 游戏更新/换补丁后失效？ | 映射或字体可能变化，需重新按本文流程生成 |
| 我有 UIF 配置但没有字体？ | 用设备/系统 CJK 字体作为基础字体生成即可 |
| 直接改脚本文本（替换占位字）可以吗？ | 需要重写 hcb（长度/偏移敏感）且可能触发校验，不建议；字体方案改动最小 |

## 附录 C：参考脚本

### C.1 `extract_map.py`（从 DLL 启发式提取内嵌映射）

```python
#!/usr/bin/env python3
"""从注入 DLL 中提取 (占位字 -> 目标字) 映射。用法: extract_map.py Game.hcb Inject.dll"""
import sys
import struct
import collections


def hcb_chars(path, limit=8_000_000):
    data = open(path, 'rb').read(limit)
    chars = collections.Counter()
    i = 0
    while i < len(data) - 2:
        if data[i] == 0x0E:                      # pushstring <u8 len> <bytes>
            ln = data[i + 1]
            if 0 < ln < 200 and i + 2 + ln <= len(data):
                raw = data[i + 2:i + 2 + ln]
                if raw.endswith(b'\x00'):
                    raw = raw[:-1]
                if b'\x00' not in raw:
                    try:
                        chars.update(raw.decode('cp932'))
                    except Exception:
                        pass
        i += 1
    return chars


def is_cjk(v):
    return (0x4E00 <= v <= 0x9FFF) or (0x3400 <= v <= 0x4DBF) or (0xF900 <= v <= 0xFAFF)


def is_sjis(v):
    if not (0x8140 <= v <= 0xFCFC):
        return False
    lead, trail = v >> 8, v & 0xFF
    return (0x81 <= lead <= 0x9F or 0xE0 <= lead <= 0xEF) and \
           (0x40 <= trail <= 0x7E or 0x80 <= trail <= 0xFC)


def is_target(v):
    # 目标字几乎都是非 ASCII 可打印字符（汉字/标点/符号）；排除控制区与代理区
    if v < 0x00A0 or 0xD800 <= v <= 0xDFFF:
        return False
    return True


def scan(dll, script_chars, key_test, min_entries=200):
    best = None
    off = 0
    while off + 4 <= len(dll):
        k, v = struct.unpack_from('<HH', dll, off)
        if not (key_test(k) and is_target(v)):
            off += 2
            continue
        table, n = {}, 0
        while off + n * 4 + 4 <= len(dll):
            k2, v2 = struct.unpack_from('<HH', dll, off + n * 4)
            if not (key_test(k2) and is_target(v2)):
                break
            table[chr(k2)] = chr(v2)
            n += 1
        if n >= min_entries:
            hit = len(set(table) & script_chars)
            precision = hit / n
            if precision >= 0.5 and (best is None or hit > best[0]):
                best = (hit, precision, off, n, table)
                if hit == n:
                    return best
        off += 2
    return best


def main():
    hcb_path, dll_path = sys.argv[1], sys.argv[2]
    script_chars = {c for c, n in hcb_chars(hcb_path).items() if n >= 1}
    dll = open(dll_path, 'rb').read()

    # 两种常见表格式：key 为占位字 Unicode / key 为 SJIS 码位
    for label, key_test in (('unicode', is_cjk), ('sjis', is_sjis)):
        best = scan(dll, script_chars, key_test)
        if best is None:
            continue
        hit, precision, off, n, table = best
        with open('fvp_map.tsv', 'w', encoding='utf-8') as f:
            for k, v in sorted(table.items()):
                f.write(f'{k}\t{v}\n')
        print(f'[{label}] 已导出 fvp_map.tsv：dll:0x{off:x}，{n} 条，'
              f'脚本命中 {hit}，precision {precision:.1%}')
        return
    print('未找到有效候选表')


if __name__ == '__main__':
    main()
```

### C.2 `build_remap_font.py`（生成重映射字体）

```python
#!/usr/bin/env python3
"""用映射表把基础字体改写成重映射字体（只改 cmap）。
用法: build_remap_font.py Base.otf fvp_map.tsv Out.otf
"""
import sys
from fontTools.ttLib import TTFont

def load_pairs(path):
    pairs = {}
    for line in open(path, encoding='utf-8'):
        line = line.rstrip('\n')
        if '\t' in line:
            k, v = line.split('\t')[:2]
            if len(k) == 1 and len(v) == 1:
                pairs[ord(k)] = ord(v)
    return pairs

def main():
    base, map_path, out = sys.argv[1], sys.argv[2], sys.argv[3]
    pairs = load_pairs(map_path)
    font = TTFont(base)
    subtables = 0
    missing = 0
    for table in font['cmap'].tables:
        if not table.isUnicode():
            continue
        for src, dst in pairs.items():
            glyph = table.cmap.get(dst)
            if glyph is None:
                missing += 1
                continue
            table.cmap[src] = glyph
        subtables += 1
    font.save(out)
    print(f'cmap 子表 {subtables} 个，缺失目标 {missing} 条 -> {out}')

if __name__ == '__main__':
    main()
```
